# 9) Agent Evaluator (에이전트 행동 검증)

## 개발 Principle (Context Engineering 관점)

- **Code ≠ Correctness**: 에이전트가 코드를 작성했다고 해서 올바른 결과물을 생성한 것은 아니다. 형식적으로는 "완료"처럼 보이지만 실제로는 품질이 낮을 수 있다.
- **Deterministic + LLM-based**: 검증은 두 가지로 나뉜다. **코드 기반 검증**(스키마, 형식, 규칙)은 빠르고 결정적이다. **LLM 기반 검증**(품질, 의미)은 주관적 판단이 필요한 부분을 평가한다.
- **Artifact-Based Evaluation**: 에이전트의 행동을 직접 테스트하기보다, 에이전트가 생성한 **산출물(artifact)**을 검증한다.
- **Weighted Scoring**: 각 평가 항목에 가중치를 부여하여 종합 점수를 계산한다.

## 시나리오 (Long-Running Agent 맥락)

### 배경

Anthropic 아티클의 핵심 인사이트:

> 에이전트가 "완료"라고 선언해도 실제로는 버그가 있거나 불완전할 수 있다. **체계적인 검증 시스템**이 없으면 에이전트의 출력을 신뢰할 수 없다.

### 문제

- 에이전트가 "완료"라고 해도 실제로는 불완전
- 형식은 맞지만 품질이 낮은 경우 감지 어려움
- 수동 검증은 시간 소요
