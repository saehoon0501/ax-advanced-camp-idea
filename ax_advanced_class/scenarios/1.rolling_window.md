## 1) Rolling Window (슬라이딩 컨텍스트 윈도우)

### 개발 Principle (Context Engineering 관점)
- **컨텍스트 예산(Context Budget)**: LLM 입력에는 토큰 한도가 있고, “한도 직전”이 아니라 **한도보다 훨씬 전(Pre-rot 구간)**부터 품질 저하(환각/누락/지시 불이행)가 발생할 수 있다.
- **Recency 우선순위**: 대부분의 대화형 에이전트는 최근 메시지의 영향력이 크므로 **최신 대화를 보존**하고 오래된 대화는 축소/제거해야 한다.
- **불변 컨텍스트(Immutable Context)**: 시스템 정책/규칙(예: System Prompt)은 절대 제거되면 안 된다. “메시지 0번은 보존”은 실무에서 흔한 안전장치다.
- **결정적 동작(Determinism)**: 컨텍스트 정리는 모델 호출 전에 실행되는 “전처리”이며, 가능한 한 **결정적이고 테스트 가능한 로직**으로 구현한다.

### 시나리오 (실습 맥락)
- **상황**: `MessageHistory`가 있고, `max_tokens=500` 같은 제한이 있다. 이미 50개의 짧은 메시지가 누적되어 있다.
- **도구/가정**: `count_tokens(messages)` 같은 토큰 추정 함수(모의 구현)가 제공된다.
- **문제**: 한도를 넘지 않도록 오래된 메시지를 지우되, **System Prompt(인덱스 0)는 항상 유지**해야 한다.

### 학습 목표
- **토큰 한도 기반 Pruning**을 구현하고, “항상 보존해야 하는 메시지”를 다룬다.
- **최근성 보존 + 정책 보존**이라는 컨텍스트 엔지니어링의 기본 패턴을 익힌다.

### 요구사항 (Student Task)
`prune_messages(history)`를 구현하라.
- **반드시 만족**:
  - `messages[0]`(System Prompt)은 삭제 금지
  - 결과의 총 토큰 수가 `max_tokens` 이하
  - **가장 최신 메시지**(마지막)는 반드시 포함
- **권장 사항**:
  - “최소 삭제” 원칙: 한도를 만족하는 선에서 **가장 적게 삭제**
  - 삭제는 **오래된 순서부터**

### 입력/출력 스키마(권장)
- **입력**
  - `history.messages: List[Message]` (각 Message는 role/content를 가진다고 가정)
  - `history.max_tokens: int`
  - `count_tokens(messages) -> int`
- **출력**
  - 토큰 예산을 만족하도록 정리된 `history.messages` (in-place 또는 새로운 리스트 반환)

### 구현 가이드(의사코드) <- 필요하다면 가리기.
1. `system = messages[0]`을 별도로 보관
2. `tail = messages[1:]`를 “삭제 후보”로 둔다
3. 전체 토큰이 `max_tokens` 이하가 될 때까지 `tail`의 앞(가장 오래된 메시지)부터 pop
4. 최종 `messages = [system] + tail`

### 실패 모드 / 주의점
- **System Prompt 삭제**: 정책이 날아가면 안전/품질이 즉시 악화된다.
- **최신 메시지 삭제**: 사용자의 마지막 질문이 빠져 답변이 엉뚱해진다.
- **토큰 계산 오차**: `count_tokens`가 근사치면 경계값에서 넘칠 수 있다. 실무에서는 **여유 버퍼(예: 5~10%)**를 둔다.

### 테스트(제공/권장)
- **제공 테스트 아이디어**
  - 1000 토큰 분량을 주입 후 prune 실행
  - 총 토큰 `< 500` 확인
  - `messages[0]`이 원본 System Prompt인지 확인
  - 마지막 메시지가 유지되는지 확인
- **추가 테스트(권장)**
  - 이미 한도 이하인 경우: 변경 없음
  - System Prompt + 마지막 메시지만 남길 정도로 타이트한 경우
  - 빈 메시지/아주 긴 단일 메시지(“한 번에 pruning 불가능” 상황)

### 확장 과제(선택)
- **보존 우선순위(Importance Scoring)**: “오래되었지만 중요한 메시지(요구사항, 제약)”는 남기고 덜 중요한 것을 제거
- **요약 결합**: 오래된 메시지를 삭제하기 전에 `auto_summarizer`(시나리오 2)로 먼저 요약한 뒤 넣기
