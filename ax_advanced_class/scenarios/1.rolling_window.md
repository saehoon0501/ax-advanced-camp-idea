# 1) Rolling Window (Coding Agent Conversation Management)

## 개발 Principle (Context Engineering 관점)

- **컨텍스트 예산(Context Budget)**: Coding Agent는 긴 세션 동안 많은 Tool Call(파일 읽기, 테스트 실행 등)을 수행합니다. 이로 인해 컨텍스트 윈도우가 빠르게 채워집니다.
- **Recency 우선순위**: 에이전트의 현재 작업(디버깅 중인 에러, 방금 읽은 파일)은 오래된 대화보다 훨씬 중요합니다.
- **불변 컨텍스트(Immutable Context)**: System Prompt와 **현재 작업 중인 Feature 정보**는 절대 삭제되면 안 되는 "Anchor Context"입니다.
- **Tool Output 압축**: 긴 Tool Output(예: 1000줄의 로그)은 토큰을 가장 많이 소모하는 주범이므로 우선적으로 정리 대상이 됩니다.

## 시나리오 (Long-Running Agent 맥락)

### 배경

Coding Agent가 "feature-005: Message Streaming" 기능을 구현 중입니다.

- 세션 시작 후 20번의 턴이 지났습니다.
- `cat big_file.py` 결과, `npm test`의 긴 로그 등으로 컨텍스트가 100k 토큰에 육박합니다.
- 이제 에이전트가 코드를 수정하고 저장하려는데, "Context Length Exceeded" 에러가 발생할 위기입니다.

### 문제

가장 중요한 정보(System Prompt, Feature Spec)는 유지하면서, 덜 중요한 과거의 Tool Output과 대화 내용을 정리하여 **토큰 공간을 확보**해야 합니다.

## 학습 목표

- **Priority-based Pruning**: 메시지 유형(System, Human, AI, Tool)과 내용에 따라 삭제 우선순위를 다르게 적용하는 법을 익힙니다.
- **Anchor Context 유지**: 어떤 상황에서도 보존해야 할 핵심 정보를 식별하고 보호합니다.
- **Safe Truncation**: 대화의 흐름(Conversation Flow)을 해치지 않으면서 중간 내용을 잘라내는 기법을 배웁니다.

## 요구사항 (Student Task)

### Task 1: Priority-based Rolling Window

`prune_conversation(history: List[Message], max_tokens: int) -> List[Message]`를 구현하라.

**보존 우선순위 (높은 순)**:

1. **System Prompt** (Index 0): 절대 삭제 불가
2. **First User Message** (보통 Feature Spec 포함): 보존 권장
3. **Last N Messages** (최근 5-10개): 현재 사고 과정이므로 보존
4. **Tool Outputs**: 가장 먼저 요약되거나 삭제되어야 함
5. **Old Conversation**: 중간 대화는 요약하거나 삭제

**동작**:

1. 현재 토큰 수가 `max_tokens`를 초과하는지 확인
2. 초과 시, 우선순위가 낮은(4, 5번) 메시지부터 삭제 또는 축소
3. `messages[0]`과 최근 `N`개 메시지는 최대한 보호

### Task 2: Tool Output 축소

`truncate_tool_outputs(history: List[Message]) -> List[Message]`를 구현하라.

**동작**:

- `ToolMessage`의 content 길이가 1000자를 넘으면, 앞/뒤 일부만 남기고 중간을 `... (truncated 5000 chars) ...`로 대체
- 단, 가장 최근의 Tool Output은(에이전트가 방금 요청한 것) 보존

## 구현 가이드

### 메시지 구조 (LangChain 예시)

```python
from langchain_core.messages import SystemMessage, HumanMessage, AIMessage, ToolMessage

def get_token_count(messages):
    # 모의 토큰 계산기 (글자수 / 4)
    return sum(len(m.content) for m in messages) / 4
```

### Pruning 전략

```python
def prune_conversation(messages, max_tokens=8000):
    current_tokens = get_token_count(messages)
    if current_tokens <= max_tokens:
        return messages

    # 1. System Prompt 분리
    system_prompt = messages[0]
    others = messages[1:]

    # 2. 최근 N개 보호 (예: 5개)
    recent_n = 5
    if len(others) > recent_n:
        history = others[:-recent_n]
        recent = others[-recent_n:]
    else:
        history = []
        recent = others

    # 3. History에서 Tool Output 먼저 축소
    # ... 구현 ...

    # 4. 그래도 넘치면 History 앞부분부터 삭제
    # ... 구현 ...

    return [system_prompt] + history + recent
```

## 실패 모드 / 주의점

- **짝이 맞지 않는 Tool Call 삭제**: `AIMessage(tool_calls=...)`는 있는데 대응하는 `ToolMessage`를 삭제하면 에러가 발생할 수 있음. (LangChain 등 프레임워크에 따라 다름)
  - 해결: Tool Call과 Tool Output은 하나의 블록으로 취급하여 같이 삭제하거나 유지.
- **문맥 단절**: "위의 파일 내용을 참고해서..."라고 했는데 "위의 파일 내용"이 삭제됨.
  - 해결: 파일 읽기 Tool Output은 삭제 대신 "File: {path} (read in previous turn)" 요약으로 대체.

## 테스트 (제공/권장)

### 제공 테스트

- 10k 토큰 분량의 대화 -> 4k로 줄어드는지 확인
- System Prompt와 마지막 메시지가 살아있는지 확인
- 긴 Tool Output이 축소되었는지 확인

### 추가 테스트

- Tool Call - Tool Output 쌍이 유지되는지(혹은 같이 삭제되는지) 확인
- 이미 한도 이내일 때 원본 보존 확인

## 확장 과제 (선택)

- **Summarization 결합**: 삭제된 중간 대화를 `Auto Summarizer` (시나리오 2)를 호출해 요약문으로 대체하여 삽입.
- **Smart File Context**: 파일 읽기 결과는 대화 히스토리에 남기는 대신, 별도의 "File Context" 영역(System Prompt 근처)으로 이동시켜 관리.
