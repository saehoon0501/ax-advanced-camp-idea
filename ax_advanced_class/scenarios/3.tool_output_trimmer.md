# 3) Tool Output Trimmer (툴 출력 압축/정규화)

## 개발 Principle (Context Engineering 관점)

- **Observation Compaction**: 툴 결과(Observation)는 종종 매우 장황하다. 모델이 필요한 핵심 신호만 남기고 나머지는 제거하면 **컨텍스트 예산을 추론에 재투자**할 수 있다.
- **스키마 기반 추출(Schema-driven Extraction)**: "필요한 필드 목록"을 먼저 정의하고 그 외는 버린다. 이는 재현성과 테스트 가능성을 높인다.
- **표준화된 표현(Normalization)**: 숫자/단위/시간대를 정규화하면 모델의 후속 추론이 쉬워진다.

## 시나리오 (실습 맥락)

### 배경

- **상황**: `weather_tool`이 200줄 JSON(관측소, 풍향각, 습도, 원본 메타데이터 등)을 반환한다.

### 문제

- 에이전트는 실제로 **온도만 필요**하다.
- 불필요한 데이터가 컨텍스트를 낭비한다.
