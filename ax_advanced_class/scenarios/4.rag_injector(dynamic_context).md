## 4) RAG Injector (동적 컨텍스트 주입)

### 개발 Principle (Context Engineering 관점)
- **RAG = Dynamic Context Engineering**: “모델이 세상을 다 알도록”이 아니라, **지금 질문에 필요한 지식만 컨텍스트로 주입**한다.
- **최소 관련 컨텍스트(Minimal Relevant Context)**: 문서를 많이 넣을수록 성능이 좋아지는 게 아니라, 노이즈가 늘어 추론이 흔들린다. **관련성 높은 소수만** 주입하는 게 핵심.
- **컨텍스트의 출처 표기(Attribution)**: 주입된 지식이 어디서 왔는지(문서 ID/키)를 명시하면 모델이 “근거 기반” 답변을 만들기 쉬워진다.

### 시나리오 (실습 맥락)
- **Mock Vector Store**: `knowledge_base = {"apple": "red fruit", "sky": "blue expanse"}`
- **예시 질의**: `"Why is the sky blue?"`
- **문제**: 질의에 맞는 문서만 골라 SystemMessage로 포맷해 대화 상단에 주입한다.

### 학습 목표
- Retrieval 단계에서 **gating(선별)**과 **포맷팅(주입 형식)**을 구현한다.
- “RAG 품질”이 검색 자체보다 **주입되는 컨텍스트의 품질/형식**에 크게 좌우됨을 이해한다.

### 요구사항 (Student Task)
`retrieve_context(query, knowledge_base)`를 구현하라.
- **동작**
  - `query`와 가장 관련 있는 키/문서를 선택
  - 아래 형태의 SystemMessage(또는 유사 메시지)로 포맷하여 반환
- **권장 포맷(예시)**
  - `SystemMessage(content="Retrieved context (source=sky): blue expanse")`
- **반드시 만족**
  - 관련 없는 문서는 포함하지 않음(노이즈 최소화)

### 입력/출력 스키마(권장)
- **입력**
  - `query: str`
  - `knowledge_base: Dict[str, str]`
- **출력**
  - `List[Message]` 또는 `Message` (주입할 컨텍스트 메시지)

### 구현 가이드(간단 버전)
실습에서는 벡터 검색 대신 다음 중 하나로 단순화 가능:
- **키워드 매칭**: query에 key가 포함되면 해당 문서 선택
- **룰 기반 라우팅**: “sky/하늘/blue” → sky

### 실패 모드 / 주의점
- **과주입(over-injection)**: 관련 없는 문서까지 넣으면 모델이 헷갈린다.
- **주입 위치 실수**: 컨텍스트는 일반적으로 시스템 메시지 다음, 또는 상단에 위치해야 한다(최근 메시지보다 앞).
- **근거-지시 혼동**: 주입 메시지에 “정책/명령” 문장이 섞이면 모델이 근거를 규칙으로 오해할 수 있다.  
  - 권장: “참고 정보/근거”임을 명확히 표시

### 테스트(제공/권장)
- **제공 테스트 아이디어**
  - query `"apple"` → `"red fruit"` 포함, `"blue expanse"` 미포함
- **추가 테스트(권장)**
  - query가 어떤 키에도 매칭되지 않을 때: 빈 리스트 반환 또는 “No relevant context”

### 확장 과제(선택)
- **Top-k + 압축**: top-3 문서를 고르고, 각 문서를 1~2문장으로 압축하여 주입(시나리오 2와 결합)
- **출처/신뢰도 메타데이터**: `source_id`, `updated_at`, `confidence`를 함께 주입
