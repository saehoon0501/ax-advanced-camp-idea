# 9) Clean State Committer (세션 종료 시 깨끗한 상태 유지)

## 개발 Principle (Context Engineering 관점)

- **Clean Handoff**: 다음 세션의 에이전트는 "이전 에이전트가 무엇을 남겼는가"를 빠르게 파악해야 한다. 미완성 코드, 주석처리된 실험, 문서화되지 않은 변경은 **컨텍스트 복원 비용을 증가**시킨다.
- **Commit as Checkpoint**: Git 커밋은 단순 백업이 아니라 **"이 상태는 안전하다"는 선언**이다. 다음 에이전트는 최신 커밋부터 작업을 시작할 수 있어야 한다.
- **Documentation as Context**: 코드 변경만 커밋하면 "왜 이렇게 했는지"를 다음 세션이 추론해야 한다. **커밋 메시지 + 주석 + progress file**로 맥락을 명시적으로 전달한다.
- **No Broken States**: 에이전트가 세션 중간에 실험적 변경을 할 수 있지만, **세션 종료 시점에는 앱이 동작하는 상태**여야 한다. 그렇지 않으면 다음 세션은 "디버깅"에 컨텍스트를 낭비한다.

## 시나리오 (Long-Running Agent 맥락)

### 배경

Anthropic 아티클의 핵심 실패 모드:

> **문제**: 에이전트가 기능을 반쯤 구현하고 세션을 종료함 → 다음 세션이 "무슨 일이 있었는지" 추측하느라 시간 낭비

**해결책**: 매 세션 종료 전에 강제하는 체크리스트:

1. 모든 변경사항 커밋
2. 커밋 메시지는 형식화 (Conventional Commits)
3. Progress file 업데이트
4. 앱이 동작하는 상태 확인 (broken state면 revert)
5. 다음 세션을 위한 TODO 메모

### 예시: Before & After

#### ❌ Before (No Clean State)

```
[Session 3 ends]
Git status:
  modified: src/components/NewChatButton.tsx
  modified: src/utils/api.ts
  untracked: src/components/NewChatButton.test.tsx.backup

No commit made.
progress.md not updated.
App state: NewChatButton is half-implemented, clicking it throws error.

[Session 4 starts]
Agent: "Uh... what happened here? Let me read all these files..."
(Wastes 20 minutes understanding incomplete work)
```

#### ✅ After (With Clean State Committer)

```
[Session 3 ends]
Clean State Committer runs:
✓ All tests passing
✓ Committed: "feat(chat): Implement NewChatButton"
✓ Updated progress.md
✓ Removed backup files
✓ App is working (verified with basic test)

[Session 4 starts]
Agent: "Reading progress file... Last session completed NewChatButton. Next: feature-005. Let's go!"
(Starts productive work immediately)
```

## 학습 목표

1. 세션 종료 전 자동화된 체크리스트를 구현한다.
2. "Clean state"의 정의를 명확히 한다 (테스트 통과 + 커밋 + 문서화).
3. Broken state 감지 및 자동 복구 (revert) 전략을 설계한다.
4. 다음 세션을 위한 효과적인 handoff 메시지를 작성한다.

## 요구사항 (Student Task)

### Task 1: Clean State 체크리스트

`verify_clean_state() -> CleanStateReport`를 구현하라.

**CleanStateReport 타입**:

```python
@dataclass
class CleanStateReport:
    is_clean: bool
    issues: List[str]  # 발견된 문제들
    recommendations: List[str]  # 수정 방법
```

**검증 항목**:

1. **Uncommitted changes**: `git status`가 깨끗한가?
2. **Test status**: 모든 테스트가 통과하는가?
3. **App health**: 개발 서버가 정상 동작하는가?
4. **Temp files**: `*.backup`, `*.tmp`, `TODO.txt` 같은 임시 파일이 있는가?
5. **Progress sync**: `progress.md`가 최신 커밋과 일치하는가?

**예시 출력**:

```python
CleanStateReport(
    is_clean=False,
    issues=[
        "Uncommitted changes: 3 files modified",
        "Test failures: test_new_chat_button FAILED",
        "Temp files found: NewChatButton.tsx.backup"
    ],
    recommendations=[
        "Run: git add . && git commit -m 'feat: ...'",
        "Fix failing tests before committing",
        "Delete temporary files"
    ]
)
```

### Task 2: 자동 커밋 (Conventional Commits)

`auto_commit(feature_id: str, description: str, notes: str) -> bool`를 구현하라.

**동작**:

1. 변경된 파일 확인 (`git diff --name-only`)
2. Feature 정보 기반으로 커밋 메시지 생성:

```
feat({scope}): {description}

- {note_1}
- {note_2}
- Feature {feature_id}: passes ✓

Co-authored-by: Coding Agent <agent@ai>
```

3. `git add .` + `git commit`
4. 성공/실패 반환

**제약**:

- 커밋 메시지는 Conventional Commits 형식
- 첫 줄은 50자 이하
- 본문의 각 줄은 72자 이하

### Task 3: Broken State 복구

`recover_from_broken_state() -> bool`를 구현하라.

**동작**:

1. 기본 E2E 테스트 실행 (예: 홈페이지 로딩 + 주요 버튼 클릭)
2. 실패 시:
   - 에러 로그 캡처
   - 마지막 정상 커밋 찾기 (`git log`에서 "passes ✓" 검색)
   - `git reset --hard {last_good_commit}`
   - Progress file도 해당 시점으로 복원
3. 복구 성공 시 `True`, 실패 시 `False`

**사용 시나리오**:

```python
# 세션 종료 전
state_report = verify_clean_state()

if not state_report.is_clean:
    if "Test failures" in str(state_report.issues):
        print("⚠️  Tests failing. Attempting recovery...")
        if recover_from_broken_state():
            print("✓ Recovered to last working state")
        else:
            print("✗ Manual intervention required")
```

## 구현 가이드

### Git Status 체크
```python
def has_uncommitted_changes() -> bool:
    result = subprocess.run(
        ["git", "status", "--porcelain"],
        capture_output=True,
        text=True
    )
    return len(result.stdout.strip()) > 0

def get_uncommitted_files() -> List[str]:
    result = subprocess.run(
        ["git", "status", "--porcelain"],
        capture_output=True,
        text=True
    )
    files = []
    for line in result.stdout.strip().split("\n"):
        if line:
            # " M src/file.tsx" → "src/file.tsx"
            files.append(line[3:])
    return files
````

### 임시 파일 감지

```python
TEMP_FILE_PATTERNS = [
    "**/*.backup",
    "**/*.tmp",
    "**/*~",
    "**/TODO.txt",
    "**/.DS_Store"
]

def find_temp_files() -> List[str]:
    temp_files = []
    for pattern in TEMP_FILE_PATTERNS:
        temp_files.extend(Path(".").glob(pattern))
    return [str(f) for f in temp_files]
```

### Conventional Commits 형식 생성

```python
def format_commit_message(
    type: str,  # feat, fix, refactor, docs
    scope: str,  # chat, auth, ui
    summary: str,
    body: List[str],
    footer: str
) -> str:
    # 첫 줄: type(scope): summary
    header = f"{type}({scope}): {summary[:50]}"

    # 본문: bullet points
    body_text = "\n".join(f"- {line[:70]}" for line in body)

    # 풋터
    message = f"{header}\n\n{body_text}\n\n{footer}"
    return message
```

### 마지막 정상 커밋 찾기

```python
def find_last_working_commit() -> str | None:
    """커밋 메시지에 'passes ✓'가 있는 가장 최근 커밋"""
    result = subprocess.run(
        ["git", "log", "--all", "--grep=passes ✓", "--format=%H", "-1"],
        capture_output=True,
        text=True
    )
    commit_hash = result.stdout.strip()
    return commit_hash if commit_hash else None
```

## 실패 모드 / 주의점

### 1. 에이전트가 체크리스트를 무시하려 함

**문제**: "테스트 실패하지만 나중에 고칠게요"  
**해결**: System Prompt에 **절대 규칙**으로 명시:

```
You MUST run verify_clean_state() before ending your session.
If is_clean is False, you MUST fix all issues before ending.
Ending a session with broken state is UNACCEPTABLE.
```

### 2. Revert가 너무 공격적임

**문제**: 한 줄 버그로 10개 기능을 revert  
**해결**:

- 기능별 커밋 유지 (시나리오 7의 incremental work)
- Revert 전에 사용자/에이전트에게 확인

### 3. Progress file과 Git log가 동기화 안 됨

**문제**: Progress는 업데이트했는데 코드는 커밋 안 함  
**해결**: `auto_commit` 함수 내에서 progress file도 같이 커밋:

```python
def auto_commit(feature_id, description, notes):
    # 1. 코드 커밋
    git_commit(message)

    # 2. Progress file 업데이트
    update_progress_file(feature_id, notes)

    # 3. Progress file 커밋
    subprocess.run(["git", "add", "progress.md"])
    subprocess.run(["git", "commit", "-m", "Update progress notes"])
```

### 4. 임시 파일을 실수로 커밋

**문제**: `.backup` 파일이 Git에 들어감  
**해결**:

- `.gitignore`에 패턴 추가
- Pre-commit hook으로 감지

### 5. 커밋 메시지가 너무 짧거나 모호함

**문제**: "fix stuff", "wip"  
**해결**: `auto_commit` 함수에서 검증:

```python
def validate_commit_message(message: str) -> bool:
    if len(message) < 20:
        return False  # 너무 짧음
    if message.lower() in ["wip", "fix", "update", "change"]:
        return False  # 모호함
    return True
```

### 1. Pre-commit Hooks

# 테스트 실행

    echo "Error: Backup files found"
    exit 1

echo "✓ Pre-commit checks passed"

### 2. Commit Quality Score

커밋 메시지 품질을 점수화:

```python
def score_commit_message(message: str) -> int:
    score = 0

    # Conventional Commits 형식: +30
    if re.match(r"^(feat|fix|refactor|docs)\([\w-]+\):", message):
        score += 30

    # 본문 있음: +20
    if "\n\n" in message:
        score += 20

    # Feature ID 포함: +20
    if "feature-" in message:
        score += 20

    # 적절한 길이 (20-70자): +30
    first_line = message.split("\n")[0]
    if 20 <= len(first_line) <= 70:
        score += 30

    return score  # 0-100
```

### 3. Rollback Safety

Revert 전에 현재 상태를 별도 브랜치로 저장:

```python
def safe_rollback(target_commit: str):
    # 현재 상태 백업
    current_branch = get_current_branch()
    timestamp = datetime.now().strftime("%Y%m%d_%H%M%S")
    backup_branch = f"backup/{current_branch}_{timestamp}"

    subprocess.run(["git", "branch", backup_branch])
    print(f"Created backup branch: {backup_branch}")

    # 롤백
    subprocess.run(["git", "reset", "--hard", target_commit])
```

def estimate_next_session(next_feature: dict) -> dict:

## 실전 적용 (Main Scenario)

### Coding Agent - 세션 종료 프로세스

```python
def end_session(feature_id: str, description: str):
    print("🔍 Verifying clean state before ending session...")

    # 1. Clean state 체크
    report = verify_clean_state()

    if not report.is_clean:
        print("❌ State is not clean:")
        for issue in report.issues:
            print(f"  - {issue}")

        # 2. 자동 수정 시도
        if "Test failures" in str(report.issues):
            print("⚠️  Attempting recovery from broken state...")
            if recover_from_broken_state():
                print("✓ Recovered successfully")
            else:
                raise RuntimeError("Cannot end session with broken state")

        if "Uncommitted changes" in str(report.issues):
            print("📝 Auto-committing changes...")
            auto_commit(feature_id, description, "Auto-commit at session end")

        if "Temp files" in str(report.issues):
            temp_files = find_temp_files()
            for f in temp_files:
                Path(f).unlink()
            print(f"🗑️  Deleted {len(temp_files)} temp files")

    # 3. Final verification
    final_report = verify_clean_state()
    if not final_report.is_clean:
        raise RuntimeError(f"Could not achieve clean state: {final_report.issues}")

    # 4. Handoff message
    next_feature = select_next_feature(load_json("feature_list.json"))
    handoff = generate_handoff_message(
        feature_id=feature_id,
        next_priority=next_feature["id"] if next_feature else "COMPLETE"
    )

    # 5. Update progress file
    prepend_to_file("progress.md", handoff + "\n\n")
    subprocess.run(["git", "add", "progress.md"])
    subprocess.run(["git", "commit", "-m", "Add session handoff notes"])

    print("✅ Session ended cleanly. Ready for next agent.")
```

### System Prompt Template

```
At the END of each session, you MUST:

1. Run verify_clean_state()
2. Fix all issues until is_clean=True:
   - Commit all changes
   - Ensure all tests pass
   - Remove temporary files
   - Verify app is working
3. Generate handoff message for next session
4. Update progress.md

NEVER end your session with:
- Uncommitted changes
- Failing tests
- Broken app state
- Missing documentation

The next agent depends on your clean handoff!
```
