# 5) Git Progress Tracker (Git 기반 진행 상황 추적)

## 개발 Principle (Context Engineering 관점)

- **Git as State Persistence**: Git은 단순 버전 관리가 아니라 **에이전트의 장기 기억 저장소**다. 각 커밋은 "무엇을 했고, 왜 했는지"를 담은 상태 스냅샷이다.
- **Commit Messages as Context**: 좋은 커밋 메시지는 새 세션의 Coding Agent가 "이전 세션이 무엇을 했는지"를 빠르게 파악하게 한다. 형식화된 메시지가 파싱을 쉽게 만든다.
- **Progress File as Supplement**: Git log만으로는 "왜 이 결정을 했는지", "다음엔 무엇을 해야 하는지" 같은 맥락이 부족하다. **progress.md** 같은 보조 파일로 보완한다.
- **Revert as Safety Net**: 에이전트가 잘못된 변경을 했을 때, `git revert`로 안전하게 복구할 수 있다. 이는 "실험적 개발"을 가능하게 한다.

## 시나리오 (Long-Running Agent 맥락)

### 배경

Anthropic 아티클의 핵심 패턴:

1. **Initializer Agent**: 프로젝트 초기화 시 Git repo 생성 + 첫 커밋
2. **Coding Agent**: 매 세션마다
   - 시작: `git log` 읽고 이전 작업 파악
   - 종료: 의미 있는 커밋 + `progress.md` 업데이트

### 예시 Git History

```

commit def456

    feat(theme): Add dark mode toggle

    - Implemented ThemeSwitcher component
    - CSS variables for light/dark themes

```

### progress.md 예시

```markdown

**Next priority**: feature-005 (Message streaming)
**Known issues**:
```

## 학습 목표

1. Git을 "에이전트 간 통신 수단"으로 사용하는 패턴을 익힌다.
2. 형식화된 커밋 메시지가 파싱 가능성을 높이는 원리를 이해한다.
3. Progress file과 Git log의 **역할 분리**를 명확히 한다.
   - Git log: 무엇을 변경했는지 (코드 diff)
   - Progress file: 왜 그렇게 했는지, 다음엔 무엇을 할지 (맥락)

## 요구사항 (Student Task)

### Task 1: Initializer Agent - Git 초기화

`initialize_git_repo(project_name: str) -> None`을 구현하라.

**동작**:

1. `git init` 실행
2. `.gitignore` 생성 (예: `node_modules/`, `__pycache__/`, `*.log`)
3. 초기 파일 추가 (feature_list.json, init.sh, README.md)
4. 첫 커밋: `"Initial commit: Project setup for {project_name}"`
5. `progress.md` 생성 및 커밋

**검증**:

```bash
git log --oneline | wc -l  # >= 2 (setup + progress file)
```

### Task 2: Coding Agent - 세션 시작 시 상태 복원

`recover_context_from_git() -> dict`를 구현하라.

**동작**:

1. 현재 디렉토리 확인 (`pwd`)
2. 최근 10개 커밋 읽기 (`git log --oneline -10`)
3. `progress.md` 파일 읽기
4. 파싱하여 반환:

```python
{
    "last_completed_feature": "feature-001",
    "next_priority": "feature-005",
    "known_issues": ["Theme switch flash"],
    "recent_commits": [
        {"hash": "abc123", "message": "feat(chat): Implement new chat button"},
        ...
    ]
}
```

### Task 3: Coding Agent - 세션 종료 시 상태 저장

`commit_progress(feature_id: str, description: str, notes: str) -> None`을 구현하라.

**동작**:

1. 변경된 파일 stage (`git add .`)
2. 형식화된 커밋 메시지 작성:

```
feat({category}): {description}

- Detail 1
- Detail 2
- Feature {feature_id}: passes ✓
```

3. 커밋 실행
4. `progress.md` 업데이트 (세션 정보 prepend)
5. Progress file도 커밋

**형식 규칙**:

- 첫 줄: `feat/fix/refactor({scope}): {summary}` (Conventional Commits)
- 본문: 구체적 변경사항 (bullet points)
- 푸터: Feature ID + 상태

## 구현 가이드

### Git 커맨드 실행 (Python)

```python
import subprocess

def run_git_command(args: list[str]) -> str:
    result = subprocess.run(
        ["git"] + args,
        capture_output=True,
        text=True,
        check=True
    )
    return result.stdout.strip()

# 예시
run_git_command(["log", "--oneline", "-10"])
run_git_command(["add", "."])
run_git_command(["commit", "-m", message])
```

### Commit Message 파싱

```python
import re

def parse_commit_message(message: str) -> dict:
    # "feat(chat): Implement button"
    match = re.match(r"(\w+)\(([^)]+)\): (.+)", message)
    if match:
        return {
            "type": match.group(1),      # feat
            "scope": match.group(2),     # chat
            "summary": match.group(3)    # Implement button
        }
    return {"type": "unknown", "summary": message}
```

### Progress File 포맷

```python
def update_progress_file(feature_id: str, notes: str):
    timestamp = datetime.now().strftime("%Y-%m-%d %H:%M")
    new_entry = f"""
## Session {get_session_count() + 1} ({timestamp})
**Completed**: {feature_id}
**Next priority**: {get_next_feature_id()}
**Notes**: {notes}
"""

    # 파일 상단에 추가 (최신이 위로)
    with open("progress.md", "r+") as f:
        content = f.read()
        f.seek(0)
        f.write(new_entry + "\n" + content)
```

## 실패 모드 / 주의점

### 1. 커밋 없이 세션 종료

**문제**: 에이전트가 코드를 변경했지만 커밋하지 않고 세션 종료  
**결과**: 다음 세션에서 변경 사항을 알 수 없음  
**해결**: System Prompt에 "세션 종료 전 반드시 커밋" 명시

### 2. 커밋 메시지가 장황하거나 형식 없음

**문제**: "Fixed some stuff and added things"  
**결과**: 다음 에이전트가 무엇을 했는지 파악 불가  
**해결**: Conventional Commits 포맷 강제 + 예시 제공

### 3. Progress file과 Git log의 불일치

**문제**: Progress file에는 "feature-005 완료"인데 Git log에는 없음  
**해결**:

- `commit_progress` 함수에서 두 작업을 원자적으로 처리
- 검증 로직 추가: "Progress file의 마지막 feature ID == 최신 커밋의 feature ID"

### 4. Merge conflicts (고급)

**문제**: 여러 에이전트가 병렬로 작업 시 충돌  
**해결**: 이번 실습 범위 밖. 프로덕션에서는 lock mechanism 필요

### 5. 민감 정보 커밋

**문제**: API 키, 비밀번호가 코드에 포함되어 커밋  
**해결**: Pre-commit hook으로 감지 + `.gitignore` 철저히

## 확장 과제 (선택)

### 1. Git Revert Capability

에이전트가 "이 변경이 버그를 만들었다"고 판단하면 자동으로 revert:

```python
def revert_last_commit(reason: str):
    run_git_command(["revert", "HEAD", "--no-edit"])
    update_progress_file("REVERTED", f"Reason: {reason}")
```

### 2. Branch-based Development

각 feature를 별도 브랜치에서 개발 후 merge:

```python
def start_feature(feature_id: str):
    branch_name = f"feature/{feature_id}"
    run_git_command(["checkout", "-b", branch_name])

def complete_feature(feature_id: str):
    run_git_command(["checkout", "main"])
    run_git_command(["merge", f"feature/{feature_id}", "--no-ff"])
```

### 3. 자동 Changelog 생성

Git log에서 Conventional Commits 파싱하여 CHANGELOG.md 자동 생성:

```markdown
# Changelog

## [Unreleased]

### Features

- feat(chat): Implement new chat button (feature-001)
- feat(theme): Add dark mode toggle (feature-002)

### Fixes

- fix(chat): Resolve message duplicate issue
```

## 실전 적용 (Main Scenario)

### Initializer Agent Prompt

```
At the end of initialization:
1. Run `git init`
2. Create .gitignore, feature_list.json, init.sh
3. Commit: "Initial commit: Project setup for {project_name}"
4. Create progress.md
5. Commit: "Add progress tracking file"
```

### Coding Agent Prompt

```
At the START of each session:
1. Run `pwd` to see current directory
2. Run `git log --oneline -10` to see recent work
3. Read progress.md to understand context
4. Decide which feature to work on

At the END of each session:
1. Stage all changes: `git add .`
2. Commit with format: "feat({scope}): {description}\n\n- Details\n- Feature {id}: passes ✓"
3. Update progress.md with session summary
4. Commit progress file: "Update progress notes"

NEVER end session without committing your work.
```
