# 8) End-to-End Test Validator (브라우저 자동화 테스트)

## 개발 Principle (Context Engineering 관점)

- **Code ≠ Correctness**: 코드가 작성되었다고 해서 기능이 동작하는 것은 아니다. 에이전트는 코드 레벨에서는 "정상"으로 보이지만 실제로는 작동하지 않는 기능을 "완료"로 표시하는 경향이 있다.
- **User Perspective Testing**: End-to-end 테스트는 **사용자가 실제로 하는 행동**을 시뮬레이션한다. 이를 통해 통합 버그, UI 버그, 타이밍 이슈 등을 발견할 수 있다.
- **Observation as Context**: 브라우저 자동화 도구의 출력 (스크린샷, 로그)은 컨텍스트에 포함되어야 하지만, **매우 장황**할 수 있다. Tool Output Trimmer (시나리오 3)와 결합이 필요하다.
- **Testing as Documentation**: 잘 작성된 E2E 테스트는 "이 기능이 무엇을 해야 하는가"를 명확히 보여주는 실행 가능한 문서다.

## 시나리오 (Long-Running Agent 맥락)

### 배경

Anthropic 아티클의 핵심 문제:

> **초기 실패**: Claude는 코드를 작성하고 단위 테스트나 `curl` 명령으로 검증했지만, **실제로 브라우저에서 동작하지 않는 경우**를 "완료"로 표시했다.

**해결책**: Puppeteer/Playwright 같은 브라우저 자동화 도구를 사용해 **사람처럼 테스트**하도록 강제.

### 예시: Before & After

#### ❌ Before (No E2E Testing)

```python
# Coding Agent의 작업
def implement_new_chat_button():
    # NewChatButton 컴포넌트 생성
    write_file("NewChatButton.tsx", component_code)

    # 단위 테스트
    assert NewChatButton renders without errors  ✓

    # Agent: "완료!"
    mark_feature_complete("feature-001")

# 실제로는...
# - Button이 렌더링되지만 클릭 이벤트가 연결 안 됨
# - 새 채팅이 생성되지 않음
# - 사용자는 버그를 경험
```

#### ✅ After (With E2E Testing)

```python
def implement_new_chat_button():
    # 코드 작성
    write_file("NewChatButton.tsx", component_code)

    # 단위 테스트
    assert NewChatButton renders  ✓

    # E2E 테스트
    browser = launch_browser()
    browser.goto("http://localhost:3000")
    browser.click('[data-testid="new-chat-button"]')

    # 검증
    assert browser.is_visible('.chat-welcome-message')  ✗ FAILED
    # Agent: "아직 완료 안 됨, 이벤트 핸들러를 고치자"

    fix_event_handler()
    run_e2e_test()  ✓ PASSED

    # 이제 진짜 완료
    mark_feature_complete("feature-001")
```

### Anthropic의 실제 사례

Article에서 소개된 스크린샷:

- Claude가 Puppeteer MCP를 사용해 claude.ai clone을 테스트
- 실제 브라우저에서 버튼 클릭, 입력, 응답 확인
- 스크린샷으로 시각적 버그도 발견

## 학습 목표

1. Puppeteer/Playwright를 사용한 브라우저 자동화를 익힌다.
2. Feature의 `steps`를 E2E 테스트 코드로 변환하는 방법을 이해한다.
3. 테스트 실패 시 디버깅 정보 (스크린샷, 로그)를 효율적으로 캡처한다.
4. E2E 테스트 출력을 컨텍스트 친화적으로 압축한다.

## 요구사항 (Student Task)

### Task 1: Feature Steps → E2E Test 변환

`generate_e2e_test(feature: dict) -> str`를 구현하라.

**입력 예시**:

```json
{
  "id": "feature-001",
  "description": "New chat button creates a fresh conversation",
  "steps": [
    "Navigate to main interface",
    "Click the 'New Chat' button",
    "Verify a new conversation is created",
    "Check that chat area shows welcome state",
    "Verify conversation appears in sidebar"
  ]
}
```

**출력 예시** (Python + Playwright):

```python
async def test_feature_001():
    """Test: New chat button creates a fresh conversation"""
    async with async_playwright() as p:
        browser = await p.chromium.launch()
        page = await browser.new_page()

        # Step 1: Navigate to main interface
        await page.goto("http://localhost:3000")

        # Step 2: Click the 'New Chat' button
        await page.click('[data-testid="new-chat-button"]')

        # Step 3: Verify a new conversation is created
        conversation = await page.wait_for_selector('.conversation-item')
        assert conversation is not None

        # Step 4: Check that chat area shows welcome state
        welcome = await page.query_selector('.chat-welcome-message')
        assert welcome is not None

        # Step 5: Verify conversation appears in sidebar
        sidebar_item = await page.query_selector('.sidebar .conversation-item')
        assert sidebar_item is not None

        await browser.close()
```

**제약**:

- 각 `step`이 하나 이상의 assertion으로 변환되어야 함
- 테스트 실패 시 스크린샷 자동 저장

### Task 2: E2E Test 실행 및 결과 수집

`run_e2e_test(feature_id: str) -> TestResult`를 구현하라.

**TestResult 타입**:

```python
@dataclass
class TestResult:
    feature_id: str
    passed: bool
    duration_seconds: float
    error_message: str | None
    screenshot_path: str | None
    console_logs: List[str]
```

**동작**:

1. 개발 서버가 실행 중인지 확인 (없으면 `./init.sh` 실행)
2. 해당 feature의 E2E 테스트 실행
3. 실패 시:
   - 에러 메시지 캡처
   - 스크린샷 저장 (`screenshots/{feature_id}_failure.png`)
   - 브라우저 콘솔 로그 수집
4. 결과 반환

### Task 3: 테스트 결과 압축 (Context-Friendly)

`summarize_test_result(result: TestResult) -> str`를 구현하라.

**목적**: 상세한 테스트 결과를 에이전트 컨텍스트에 주입할 때, 핵심만 남기기

**입력** (장황한 결과):

```python
TestResult(
    feature_id="feature-001",
    passed=False,
    duration_seconds=12.5,
    error_message="Timeout: element '[data-testid=\"new-chat-button\"]' not found after 5000ms\n  at Page.click (/node_modules/playwright/...)\n  ... (50 lines of stack trace)",
    screenshot_path="screenshots/feature-001_failure.png",
    console_logs=[
        "Warning: React does not recognize the `testID` prop...",
        "Error: Cannot read property 'id' of undefined",
        ... (100 lines)
    ]
)
```

**출력** (압축):

```
❌ feature-001 FAILED (12.5s)
Error: Element '[data-testid="new-chat-button"]' not found
Key console error: Cannot read property 'id' of undefined
Screenshot: screenshots/feature-001_failure.png
```

**압축 규칙**:

- Stack trace의 첫 줄만
- Console logs에서 `Error:` 포함된 것만
- Screenshot 경로는 유지

### Playwright Setup (Python)

```bash
pip install playwright
playwright install chromium
```

```python
from playwright.async_api import async_playwright

async def run_test():
    async with async_playwright() as p:
        browser = await p.chromium.launch(headless=True)  # CI에서는 headless
        page = await browser.new_page()

        # 콘솔 로그 캡처
        console_logs = []
        page.on("console", lambda msg: console_logs.append(msg.text))

        try:
            await page.goto("http://localhost:3000", wait_until="networkidle")
            await page.click('[data-testid="button"]')
            # ...
            return TestResult(passed=True, ...)
        except Exception as e:
            # 실패 시 스크린샷
            await page.screenshot(path=f"screenshots/{feature_id}_failure.png")
            return TestResult(passed=False, error_message=str(e), ...)
        finally:
            await browser.close()
```

### Step → Code 변환 휴리스틱

```python
def step_to_code(step: str) -> str:
    """Simple rule-based conversion"""
    step_lower = step.lower()

    if "navigate" in step_lower or "goto" in step_lower:
        return 'await page.goto("http://localhost:3000")'

    if "click" in step_lower:
        # "Click the 'New Chat' button" → extract button text
        match = re.search(r"'([^']+)'", step)
        if match:
            text = match.group(1)
            return f'await page.click(\'text="{text}"\')'

    if "verify" in step_lower or "check" in step_lower:
        # "Verify X appears" → assertion
        return f'assert await page.query_selector(".expected-element") is not None'

    return f'# TODO: {step}'
```

### 개발 서버 Health Check

```python
import requests
import subprocess
import time

def ensure_dev_server_running(port: int = 3000, timeout: int = 30):
    """서버가 없으면 시작"""
    try:
        response = requests.get(f"http://localhost:{port}", timeout=2)
        if response.status_code == 200:
            return True  # 이미 실행 중
    except requests.RequestException:
        pass

    # 서버 시작
    print("Starting dev server...")
    subprocess.Popen(["./init.sh"], stdout=subprocess.DEVNULL, stderr=subprocess.DEVNULL)

    # 준비 대기
    for _ in range(timeout):
        try:
            response = requests.get(f"http://localhost:{port}", timeout=2)
            if response.status_code == 200:
                print("Dev server ready!")
                return True
        except requests.RequestException:
            time.sleep(1)

    raise RuntimeError("Dev server failed to start")
```

## 실패 모드 / 주의점

### 1. 개발 서버가 안 뜰 때

**문제**: `./init.sh` 실행 실패, 포트 충돌 등  
**해결**:

- Health check에서 에러 로그 캡처
- 다른 포트 시도 또는 사용자에게 알림

### 2. Selector가 불안정함

**문제**: `.button`처럼 일반적인 클래스는 여러 요소에 매칭  
**해결**: `data-testid` 속성 사용 권장

```html
<button data-testid="new-chat-button">New Chat</button>
```

### 3. 타이밍 이슈 (Race condition)

**문제**: 요소가 아직 렌더링 안 됐는데 클릭 시도  
**해결**: `wait_for_selector` 사용

```python
await page.wait_for_selector('[data-testid="button"]', state="visible", timeout=5000)
await page.click('[data-testid="button"]')
```

### 4. 스크린샷/로그가 컨텍스트를 너무 차지함

**문제**: 고해상도 스크린샷, 수백 줄 로그  
**해결**:

- 스크린샷은 파일로만 저장, 컨텍스트에는 경로만
- 로그는 `Error:`만 필터링

### 5. Headless vs Headed 모드

**문제**: Headless에서는 통과하는데 실제 브라우저에서 실패 (또는 반대)  
**해결**:

- CI는 headless
- 로컬 디버깅은 headed (`headless=False`)

```python
def test_generate_e2e_test():
    """Step 변환"""
    feature = {
        "id": "feature-001",
        "description": "Test feature",
        "steps": [
            "Navigate to homepage",
            "Click the 'Submit' button",
            "Verify success message appears"
        ]
    }

    code = generate_e2e_test(feature)

    assert "page.goto" in code
    assert "page.click" in code
    assert "assert" in code

@pytest.mark.asyncio
async def test_run_e2e_test_pass(mock_app):
    """테스트 성공 케이스"""
    # mock_app은 간단한 웹 서버 fixture
    result = await run_e2e_test("feature-001")

    assert result.passed == True
    assert result.duration_seconds > 0
    assert result.error_message is None

@pytest.mark.asyncio
async def test_run_e2e_test_fail(mock_broken_app):
    """테스트 실패 케이스"""
    result = await run_e2e_test("feature-002")

    assert result.passed == False
    assert result.error_message is not None
    assert result.screenshot_path is not None
    assert Path(result.screenshot_path).exists()

def test_summarize_test_result():
    """결과 압축"""
    result = TestResult(
        feature_id="feature-001",
        passed=False,
        duration_seconds=12.5,
        error_message="Timeout: element not found\n  at Page.click (/long/path)\n  ... (많은 stack trace)",
        screenshot_path="screenshots/feature-001_failure.png",
        console_logs=["Info: Starting", "Error: Cannot read property", "Debug: ..."]
    )

    summary = summarize_test_result(result)

    assert "feature-001" in summary
    assert "12.5s" in summary
    assert "Cannot read property" in summary
    assert len(summary) < 200  # 압축되었는지
```

## 실전 적용 (Main Scenario)

### Coding Agent Workflow

```python
async def implement_feature(feature: dict):
    # 1. 코드 작성
    write_code(feature)

    # 2. 단위 테스트
    unit_test_result = run_unit_tests()
    if not unit_test_result.passed:
        fix_code()

    # 3. E2E 테스트 생성 (처음에만)
    if not Path(f"tests/e2e/test_{feature['id']}.py").exists():
        e2e_code = generate_e2e_test(feature)
        write_file(f"tests/e2e/test_{feature['id']}.py", e2e_code)

    # 4. E2E 테스트 실행
    e2e_result = await run_e2e_test(feature["id"])

    if not e2e_result.passed:
        # 5. 실패 원인 분석
        summary = summarize_test_result(e2e_result)
        print(f"E2E test failed:\n{summary}")

        # 6. 에이전트에게 피드백
        agent.invoke({
            "messages": [
                HumanMessage(content=f"E2E test failed. Fix the issue:\n{summary}")
            ]
        })

        # 7. 재시도
        return await implement_feature(feature)

    # 8. 성공!
    mark_feature_complete(feature["id"])
```

### System Prompt Addition

```
Before marking any feature as complete, you MUST:
1. Generate an E2E test from the feature steps
2. Run the E2E test and ensure it passes
3. If the test fails, analyze the error and fix the code
4. Do NOT mark passes=true until the E2E test succeeds

E2E tests simulate real user behavior. Passing unit tests is not enough.
```
