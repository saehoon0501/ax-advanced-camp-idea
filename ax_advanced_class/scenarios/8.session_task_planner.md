# 8) Session Task Planner (세션 내 작업 계획 및 추적)

## 개발 Principle (Context Engineering 관점)

- **Planning as Context Anchor**: 에이전트가 "다음에 뭘 해야 하지?"를 매번 재계산하면 컨텍스트를 낭비한다. **세션 시작 시 계획을 세우고 참조**하면 일관된 진행이 가능하다.
- **Todolist as Working Memory**: 컨텍스트 윈도우가 길어지면 에이전트는 초기 의도를 잊어버린다. **명시적 todolist**는 "지금 해야 할 일"을 상기시키는 **외부 메모리** 역할을 한다.
- **Progress Visibility**: 사용자와 다음 세션의 에이전트 모두 "현재 어디까지 왔는가"를 한눈에 파악해야 한다.
- **Preventing Scope Drift**: Todolist에 없는 작업을 시작하면 scope creep이 발생한다. "Todolist에 있는 것만 한다"는 규칙이 **집중력을 유지**시킨다.

## 시나리오 (Long-Running Agent 맥락)

### 배경

Anthropic 아티클의 핵심 인사이트:

> **문제**: 에이전트가 기능 구현 중 "이것도 해야겠다, 저것도 해야겠다"하며 산만해짐 → 결국 아무것도 완성 못 함

### 문제

**Before (No Task Planning)**:

```
[Session starts]
Agent: "feature-003을 구현하겠습니다!"
→ NewChatButton 컴포넌트 만들기 시작
→ "아, 스타일도 필요하네" → CSS 작성
→ "테스트도 만들어야지" → 테스트 작성 시작
→ "어, 이 API 호출이 이상하네" → API 수정
→ 컨텍스트 소진

결과: 모든 것이 50% 완성, 아무것도 완료되지 않음
```
