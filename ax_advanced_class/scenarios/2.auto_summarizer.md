# 2) Auto Summarizer (Agent 내부 대화 압축)

## 개발 Principle (Context Engineering 관점)

- **Long-Running Agent Sessions**: Coding Agent가 복잡한 기능을 구현할 때, 수십 번의 tool call과 디버깅 과정을 거친다. 이 과정에서 컨텍스트가 빠르게 소진된다.
- **Lossy Compression with Meaning Preservation**: 오래된 대화를 삭제하는 대신, **핵심 의미를 보존한 요약**으로 압축한다. 이를 통해 중요한 결정사항과 맥락을 유지하면서 토큰을 절약한다.
- **Hierarchical Memory**: 최근 메시지는 원문 유지 (정확도), 과거 메시지는 요약으로 유지 (효율성).
- **Middleware Pattern**: 이 기능은 **middleware로 구현**되어 Initializer Agent와 Coding Agent 모두에 자동 적용된다.

## 시나리오 (Long-Running Agent 맥락)

### 배경

Coding Agent가 "feature-005: Message Streaming" 기능을 구현 중입니다:

```
[Turn 1] AI: "I'll implement message streaming"
[Turn 2] Tool: read_file("src/api.ts") → 2000 chars
[Turn 3] AI: "I see the API structure. Let me create the streaming endpoint"
[Turn 4] Tool: write_file("src/streaming.ts", ...) → 1500 chars
[Turn 5] Tool: bash("npm test") → 5000 chars of test output
[Turn 6] AI: "Tests failing. Let me check the error"
[Turn 7] Tool: read_file("src/streaming.ts") → 1500 chars
[Turn 8] AI: "Found the bug - missing async handler"
[Turn 9] Tool: edit_file(...) → 500 chars
[Turn 10] Tool: bash("npm test") → 5000 chars
[Turn 11] AI: "Still failing. Different error now..."
... (20 more turns of debugging) ...
[Turn 30] AI: "Finally! All tests passing"
```

이 middleware는 **모든 sub-agent에 적용**됩니다:

| Agent                 | 적용 이유                                            |
| --------------------- | ---------------------------------------------------- |
| **Initializer Agent** | 대규모 feature list 생성 시 많은 tool call 발생 가능 |
| **Coding Agent**      | 디버깅, 테스트 반복으로 긴 세션 발생                 |

### 문제: Context Exhaustion

**문제**: 30턴 × 평균 2000 tokens = **60,000 tokens** (컨텍스트 한계 근접)

### 심화 문제: Output Token 기반 Compaction Trigger 구현

`astream_events`의 `on_chat_model_end` 이벤트를 활용하여, output token 사용량 기반의 compaction trigger를 추가 구현하세요.

#### Hint 1: `on_chat_model_end` 이벤트 내 Token Metadata 구조

```python
event = {
    "event": "on_chat_model_end",
    "data": {
        "output": AIMessage(
            usage_metadata={
                "input_tokens": 14,
                "output_tokens": 50,
                "total_tokens": 64,
            },
            response_metadata={
                "stop_reason": "end_turn",  # 또는 "max_tokens"
            }
        )
    },
    "metadata": {
        "ls_max_tokens": 8192,
    }
}
```

#### Hint 2: Compaction 결정 로직

| 조건 | 의미 | 권장 조치 |
|------|------|-----------|
| `output_tokens / max_tokens >= 0.8` | 한계 근접 | **압축 필요** |
| `stop_reason == "end_turn"` | 정상 완료 | 압축 불필요 |
