# 6) State Recovery (Coding Agent - Git 및 Progress 파일 읽기)

## 개발 Principle (Context Engineering 관점)

- **Cold Start Problem**: Long-running agent의 핵심 문제는 "각 세션이 제로 메모리에서 시작"한다는 점이다. 이전 세션의 컨텍스트를 빠르고 정확하게 복원하는 것이 생산성의 핵심이다.
- **Git as Communication**: Git은 에이전트 간 통신 수단이다. 이전 Coding Agent가 남긴 커밋 메시지를 읽고 무엇을 했는지 파악한다.
- **Commit Messages as Context**: 좋은 커밋 메시지는 새 세션의 Coding Agent가 "이전 세션이 무엇을 했는지"를 빠르게 파악하게 한다. 형식화된 메시지가 파싱을 쉽게 만든다.
- **Multi-Source Context Reconstruction**: 상태는 하나의 소스가 아니라 **여러 소스에 분산**되어 있다:
  - **Git log**: 무엇을 변경했는지 (code diffs)
  - **Progress file**: 왜 그렇게 했는지, 다음 계획
  - **Feature list**: 전체 작업 범위와 진행률
  - **Workspace files**: 현재 코드베이스 상태
- **Progress file과 Git log의 역할 분리**:
  - Git log: 무엇을 변경했는지 (코드 diff)
  - Progress file: 왜 그렇게 했는지, 다음엔 무엇을 할지 (맥락)
- **Fast Context Loading**: 복원에 너무 오래 걸리면 컨텍스트 예산을 소모한다. **핵심 정보만 빠르게** 로딩하는 전략이 필요하다.
- **Sanity Check**: 복원된 상태가 일관성 있는지 검증해야 한다. 예: Progress file에는 "feature-005 완료"인데 feature_list.json에는 `passes=false`면 충돌.

## 시나리오 (Long-Running Agent 맥락)

### 배경

Anthropic 아티클의 핵심 패턴: Coding Agent는 매 세션 시작 시 다음을 수행한다.

```
1. Run `pwd` to see the directory you're working in
2. Read the git logs to get up to speed on what was recently worked on
3. Read progress.md to understand context and next priority
4. Read the feature list file and choose the highest-priority feature
5. Read init.sh to understand how to start the development server
6. Run basic end-to-end test to verify the app is not broken
```

### Git 및 Progress 파일 읽기 흐름

```
[Coding Agent Session Start]
       │
       ▼
   pwd (현재 위치 확인)
       │
       ▼
   git log --oneline -10 (최근 작업 파악)
       │
       ▼
   progress.md 읽기 (이전 세션의 맥락 파악)
       │
       ├── last_completed_feature
       ├── next_priority
       └── known_issues
       │
       ▼
   feature_list.json 읽기 (전체 진행률 파악)
       │
       ▼
   init.sh 실행 (개발 서버 시작)
       │
       ▼
   기본 테스트로 앱 상태 확인
       │
       ▼
   [Start working on next feature]
```

1. **빠르게** (2-3분 내)
2. **정확하게** (모든 핵심 상태 파악)
3. **검증하며** (불일치 발견 시 복구)

### Task 2: 전체 상태 복원 함수

`recover_session_state() -> SessionState`를 구현하라.

**반환 타입**:

```python
@dataclass
class SessionState:
    current_directory: str
    last_completed_feature: str
    next_priority_feature: str
    recent_commits: List[Dict[str, str]]  # [{hash, message, timestamp}]
    known_issues: List[str]
    total_features: int
    completed_features: int
    is_app_working: bool  # 기본 테스트 결과
```

**동작**:

1. `pwd` 실행하여 현재 디렉토리 확인
2. Git log 최근 10개 읽기
3. `progress.md` 파싱
4. `feature_list.json` 로드 및 통계 계산
5. (선택) `init.sh` 실행하여 기본 테스트

**제약**:

- 전체 실행 시간 < 30초 (큰 파일은 부분 읽기)
- Feature list가 200개여도 처리 가능해야 함

### Task 2: 상태 일관성 검증

`validate_state_consistency(state: SessionState) -> List[str]`를 구현하라.

**검증 항목**:

1. Progress file의 마지막 완료 feature가 feature list에서도 `passes=true`인가?
2. Git log의 최신 커밋이 progress file의 타임스탬프와 일치하는가?
3. `completed_features` 숫자가 feature list의 `passes=true` 개수와 동일한가?

**반환**: 발견된 불일치 목록 (없으면 빈 리스트)

**예시**:


## 구현 가이드

### Git Log 효율적 읽기

```python
def get_recent_commits(limit: int = 10) -> List[dict]:
    # --pretty=format으로 구조화된 출력
    result = subprocess.run(
        ["git", "log", f"-{limit}", "--pretty=format:%H|%s|%ar"],
        capture_output=True,
        text=True
    )

    commits = []
    for line in result.stdout.strip().split("\n"):
        if line:
            hash, message, time = line.split("|")
            commits.append({"hash": hash[:7], "message": message, "time": time})

    return commits
```

### Commit Message 파싱

```python
import re

def parse_commit_message(message: str) -> dict:
    # "feat(chat): Implement button" -> type, scope, summary
    match = re.match(r"(\w+)\(([^)]+)\): (.+)", message)
    if match:
        return {
            "type": match.group(1),      # feat
            "scope": match.group(2),     # chat
            "summary": match.group(3)    # Implement button
        }
    return {"type": "unknown", "summary": message}
```

## 실패 모드 / 주의점

### 1. 파일이 없을 때

**문제**: 첫 세션이거나 파일이 삭제됨  
**해결**:

```python
def recover_session_state() -> SessionState:
    if not Path("progress.md").exists():
        return SessionState.default()  # 기본값 반환
    # ...
```

### 2. Git log가 비어있을 때

**문제**: Git repo가 초기화되지 않았거나 커밋이 없음  
**해결**: `recent_commits = []`로 설정하고 계속 진행

### 3. 상태 불일치 발견 시 대응

**문제**: Progress file과 feature list가 충돌  
**해결 전략**:

```python
inconsistencies = validate_state_consistency(state)
if inconsistencies:
    # 옵션 1: Feature list를 신뢰 (더 구조화됨)
    state.last_completed_feature = get_from_feature_list()

    # 옵션 2: 사용자/에이전트에게 물어보기
    print(f"WARNING: {inconsistencies}")
    # Agent decides which source to trust
```

### 4. 복원에 너무 오래 걸림

**문제**: 큰 Git repo, 1000개 feature list 등  
**해결**:

- Git log는 최근 10개만
- Feature list는 `passes=false`인 것만 메모리에
- Progress file은 최근 3 세션만 파싱

### 5. 컨텍스트 주입이 너무 길어짐

**문제**: 복원된 정보를 모두 prompt에 넣으면 토큰 낭비  
**해결**: **요약된 형식**으로 주입 (위 `inject_context_to_prompt` 참고)

## 확장 과제 (선택)

### 1. Incremental State Loading

필수 상태만 먼저 로딩하고, 나머지는 필요 시 로딩:

```python
state = recover_session_state(fast=True)  # git log + progress file만
# ... 에이전트가 feature 선택 ...
feature_details = load_feature_details(feature_id)  # 이제 전체 feature list 로딩
```

복원한 상태를 캐싱하여 같은 세션 내 재호출 시 빠르게:

## 실전 적용 (Main Scenario)

### Coding Agent System Prompt

```
You are a Coding Agent working on a long-running project.

AT THE START OF EVERY SESSION:
1. Call recover_session_state() to understand what happened before
2. Review the injected context carefully
3. If is_app_working is False, fix the broken state BEFORE working on new features
4. Choose the next_priority_feature to work on

You are continuing the work of previous agents. Respect their decisions
and build upon their progress incrementally.
```

```python
# main.py
def coding_agent_session():
```
