# 4) Feature List Manager (Initializer Agent - 구조화된 기능 목록 생성)

## 개발 Principle (Context Engineering 관점)

- **구조화된 상태 관리**: "완료해야 할 기능들"을 텍스트로 나열하면 파싱 오류, 의미 모호성, 토큰 낭비가 발생한다. **JSON 같은 구조화 포맷**으로 저장하면 기계 판독이 쉽고 일관성이 높다.
- **JSON > Markdown**: Anthropic 아티클에서 강조한 핵심 인사이트 - 모델은 Markdown보다 **JSON을 수정할 가능성이 낮다**. 구조화된 포맷은 실수로 인한 손상을 방지한다.
- **테스트 기반 진행 추적**: 각 기능에 "passes: true/false" 같은 명확한 상태를 두면, "70% 완료" 같은 모호한 표현 없이 **정량적 진행도**를 추적할 수 있다.
- **불변성 원칙**: Feature list의 핵심 필드(id, description, steps)는 생성 후 변경되지 않는다. 상태 업데이트(passes, notes)만 허용된다.
- **Coding Agent의 작업 대기열**: 이 파일은 단순 TODO가 아니라, 이후 Coding Agent가 "다음 무엇을 할지" 결정하는 **우선순위 큐** 역할을 한다.

## 시나리오 (Long-Running Agent 맥락)

### 배경

Anthropic 아티클의 핵심 패턴:

> Initializer Agent가 사용자의 고수준 요구사항("Build a claude.ai clone")을 받아 **200+ 세부 기능을 구조화된 JSON 파일**로 생성한다.

### Initializer Agent의 역할

```
User: "Build a blog app with posts and comments"
                    │
                    ▼
┌─────────────────────────────────────────────────────────────────┐
│  INITIALIZER AGENT                                               │
│                                                                  │
│  1. Parse high-level requirements                                │
│  2. Break down into 10-50 specific, testable features           │
│  3. Assign priority (high/medium/low)                           │
│  4. Define verification steps for each feature                   │
│  5. Save as feature_list.json                                    │
│                                                                  │
│  Output: feature_list.json (structured, parseable by Coding Agent)│
└─────────────────────────────────────────────────────────────────┘
                    │
                    ▼
        [Scenario 5: progress.md, init.sh 생성]
                    │
                    ▼
        [Scenario 6, 7: Coding Agent가 읽고 사용]
```

### 왜 JSON인가? (Anthropic의 인사이트)

> "We found that using JSON for the feature list was more reliable than markdown—models seem to be less likely to inadvertently modify JSON formatting compared to markdown."

| Format | 장점 | 단점 |
|--------|------|------|
| **Markdown** | 읽기 쉬움 | 파싱 어려움, 실수로 형식 변경 가능 |
| **JSON** | 파싱 용이, 형식 보존 | 읽기 어려움 (but 에이전트는 상관없음) |

## 학습 목표

1. 텍스트 기반 TODO와 구조화된 feature tracking의 차이를 이해한다.
2. 고수준 요구사항을 **테스트 가능한 세부 기능**으로 분해하는 방법을 익힌다.
3. JSON Schema를 사용해 일관성을 강제하는 방법을 익힌다.
4. Initializer Agent가 Coding Agent를 위한 "작업 명세서"를 생성하는 패턴을 구현한다.

## 요구사항 (Student Task)

### Task 1: Feature List 생성

`create_feature_list(project_spec: str) -> dict`를 구현하라.

**입력**:

```
"Build a simple blog: users can create posts, view post list, and delete posts."
```

**출력**:

```json
{
  "project_name": "Simple Blog",
  "created_at": "2025-01-15T10:00:00Z",
  "features": [
    {
      "id": "feature-001",
      "category": "functional",
      "description": "User can create a new blog post",
      "priority": "high",
      "steps": ["Navigate to create page", "Fill title and content", "Click submit", "Verify post appears in list"],
      "passes": false,
      "last_tested": null,
      "notes": ""
    },
    ...
  ]
}
```

**제약**:

- 모든 기능은 초기 `passes=false`
- `id`는 고유해야 함 (예: `feature-{counter:03d}`)
- 각 기능은 최소 2개 이상의 검증 단계(`steps`)를 가져야 함
- `priority`는 핵심 기능 = high, UI/UX = medium, 최적화/부가기능 = low

### Task 2: Feature Breakdown 품질 검증

`validate_feature_list(feature_list: dict) -> ValidationResult`를 구현하라.

**검증 항목**:

1. **Testability**: 각 feature가 테스트 가능한가? (steps가 구체적인가?)
2. **Completeness**: 요구사항의 모든 측면이 커버되었는가?
3. **Granularity**: 기능이 너무 크거나 작지 않은가? (1-3시간 내 구현 가능?)
4. **Priority Balance**: High/Medium/Low가 적절히 분배되었는가?

**출력**:

```python
@dataclass
class ValidationResult:
    is_valid: bool
    issues: List[str]
    suggestions: List[str]
    stats: dict  # {"total": 15, "high": 5, "medium": 7, "low": 3}
```

### Task 3: JSON Schema 정의

`FEATURE_LIST_SCHEMA`를 정의하고, `validate_schema(feature_list: dict) -> bool`을 구현하라.

## 구현 가이드

### JSON Schema (검증용)

```python
FEATURE_SCHEMA = {
    "type": "object",
    "properties": {
        "id": {"type": "string", "pattern": "^feature-\\d{3}$"},
        "category": {"type": "string", "enum": ["functional", "ui", "performance", "security"]},
        "description": {"type": "string", "minLength": 10, "maxLength": 200},
        "priority": {"type": "string", "enum": ["high", "medium", "low"]},
        "steps": {"type": "array", "minItems": 2, "items": {"type": "string", "minLength": 5}},
        "passes": {"type": "boolean"},
        "last_tested": {"type": ["string", "null"]},
        "notes": {"type": "string"}
    },
    "required": ["id", "category", "description", "priority", "steps", "passes"]
}

FEATURE_LIST_SCHEMA = {
    "type": "object",
    "properties": {
        "project_name": {"type": "string"},
        "created_at": {"type": "string", "format": "date-time"},
        "features": {"type": "array", "items": FEATURE_SCHEMA, "minItems": 1}
    },
    "required": ["project_name", "features"]
}
```

### LLM을 사용한 Feature Breakdown

```python
def create_feature_list(project_spec: str, llm) -> dict:
    prompt = f"""Break down this project into specific, testable features.

Project: {project_spec}

For each feature, provide:
1. A clear, specific description (what the user can do)
2. Priority: high (core functionality), medium (important UX), low (nice-to-have)
3. Verification steps (how to test this feature works)

Output as JSON with this structure:
{{
  "project_name": "...",
  "features": [
    {{
      "id": "feature-001",
      "category": "functional|ui|performance|security",
      "description": "User can...",
      "priority": "high|medium|low",
      "steps": ["Step 1", "Step 2", ...],
      "passes": false,
      "last_tested": null,
      "notes": ""
    }}
  ]
}}

Create 10-30 features covering all aspects of the project.
Each feature should be completable in 1-3 hours.
"""

    response = llm.invoke(prompt)
    feature_list = json.loads(response.content)
    feature_list["created_at"] = datetime.now().isoformat()

    return feature_list
```

### 파일 저장

```python
def save_feature_list(feature_list: dict, path: str = "feature_list.json"):
    """JSON 파일로 저장 (들여쓰기로 가독성 확보)"""
    with open(path, "w") as f:
        json.dump(feature_list, f, indent=2, ensure_ascii=False)
```

## 실패 모드 / 주의점

### 1. 기능이 너무 큼

**문제**: "feature-001: Implement entire authentication system" (20시간 작업)
**영향**: Coding Agent가 한 세션에 완료 불가 → 미완성 상태로 세션 종료
**해결**: Initializer prompt에 "각 기능은 1-3시간 내 완료 가능하게" 명시

```python
# 좋은 예
"feature-001": "User can register with email and password"
"feature-002": "User can log in with email and password"
"feature-003": "User can log out"

# 나쁜 예
"feature-001": "Implement complete user authentication system"
```

### 2. Steps가 모호함

**문제**: steps = ["Test the feature", "Verify it works"]
**영향**: Coding Agent가 무엇을 검증해야 할지 모름
**해결**: 구체적인 검증 단계 요구

```python
# 좋은 예
steps = [
    "Navigate to /login page",
    "Enter valid email: test@example.com",
    "Enter valid password: password123",
    "Click 'Login' button",
    "Verify redirect to /dashboard",
    "Verify user name displayed in header"
]

# 나쁜 예
steps = ["Login works", "Dashboard shows"]
```

### 3. Priority가 모두 High

**문제**: 모든 기능이 `priority=high`
**영향**: 우선순위의 의미가 사라짐
**해결**: 분포 강제 (예: high 30%, medium 50%, low 20%)

### 4. JSON 파싱 오류

**문제**: LLM이 잘못된 JSON 생성
**해결**:

```python
def safe_parse_feature_list(response: str) -> dict:
    try:
        return json.loads(response)
    except json.JSONDecodeError:
        # JSON 블록 추출 시도
        match = re.search(r'\{[\s\S]*\}', response)
        if match:
            return json.loads(match.group())
        raise ValueError("Could not parse feature list from response")
```

## 테스트 (제공/권장)

### 제공 테스트

```python
def test_create_feature_list_structure():
    """기본 구조 검증"""
    spec = "Build a todo app: add, list, delete todos"
    result = create_feature_list(spec)

    assert "project_name" in result
    assert "features" in result
    assert len(result["features"]) >= 3
    assert all("id" in f for f in result["features"])
    assert all("steps" in f for f in result["features"])


def test_all_features_initially_false():
    """모든 기능이 초기 passes=false"""
    spec = "Build a simple blog"
    result = create_feature_list(spec)

    assert all(f["passes"] == False for f in result["features"])


def test_unique_feature_ids():
    """Feature ID 고유성"""
    spec = "Build a chat app"
    result = create_feature_list(spec)

    ids = [f["id"] for f in result["features"]]
    assert len(ids) == len(set(ids))  # 중복 없음


def test_steps_minimum():
    """각 기능은 최소 2개의 steps"""
    spec = "Build a blog"
    result = create_feature_list(spec)

    assert all(len(f["steps"]) >= 2 for f in result["features"])


def test_priority_distribution():
    """Priority 분포 확인"""
    spec = "Build a complete e-commerce site"
    result = create_feature_list(spec)

    priorities = [f["priority"] for f in result["features"]]
    assert "high" in priorities
    assert "medium" in priorities or "low" in priorities  # 모두 high가 아님


def test_schema_validation():
    """JSON Schema 검증"""
    spec = "Build a blog"
    result = create_feature_list(spec)

    is_valid = validate_schema(result)
    assert is_valid == True
```

### 3. 카테고리별 그룹핑

```python
def group_by_category(feature_list: dict) -> dict:
    """카테고리별로 기능 그룹화"""
    grouped = defaultdict(list)
    for f in feature_list["features"]:
        grouped[f["category"]].append(f)
    return dict(grouped)
```

## Coding Agent와의 연결

이 시나리오에서 생성된 `feature_list.json`은 이후 시나리오에서 사용됩니다:

| 시나리오 | feature_list.json 사용 방법 |
|----------|----------------------------|
| **6. State Recovery** | Coding Agent가 세션 시작 시 읽어 전체 진행률 파악 |
| **7. Incremental Work** | `passes=false`인 기능 중 하나를 선택하여 작업 |
| **8. Test Validator** | feature의 `steps`를 E2E 테스트로 변환 |
| **9. Clean State** | 완료 시 `passes=true`로 업데이트 후 커밋 |
