# 4) Feature List Manager (구조화된 기능 추적)

## 개발 Principle (Context Engineering 관점)

- **구조화된 상태 관리**: "완료해야 할 기능들"을 텍스트로 나열하면 파싱 오류, 의미 모호성, 토큰 낭비가 발생한다. **JSON 같은 구조화 포맷**으로 저장하면 기계 판독이 쉽고 일관성이 높다.
- **테스트 기반 진행 추적**: 각 기능에 "passes: true/false" 같은 명확한 상태를 두면, "70% 완료" 같은 모호한 표현 없이 **정량적 진행도**를 추적할 수 있다.
- **불변성 원칙**: Feature list는 기능 추가/제거가 아니라 **상태 업데이트만** 허용한다. 이를 통해 "프로젝트 스코프 변경" vs "진행 상황" 구분이 명확해진다.
- **에이전트의 작업 대기열**: Feature list는 단순 TODO가 아니라, Coding Agent가 매 세션 "다음 무엇을 할지" 결정하는 **우선순위 큐** 역할을 한다.

## 시나리오 (Long-Running Agent 맥락)

### 배경

Anthropic 아티클의 핵심 패턴: Initializer Agent가 사용자의 고수준 요구사항("Build a claude.ai clone")을 받아 **200+ 세부 기능을 구조화된 JSON 파일**로 생성한다.

### 예시 Feature List

```json
{
  "features": [
    {
      "id": "feature-001",
      "category": "functional",
      "description": "New chat button creates a fresh conversation",
      "priority": "high",
      "steps": [
        "Navigate to main interface",
        "Click the 'New Chat' button",
        "Verify a new conversation is created",
        "Check that chat area shows welcome state",
        "Verify conversation appears in sidebar"
      ],
      "passes": false,
      "last_tested": null,
      "notes": ""
    },
    {
      "id": "feature-002",
      "category": "ui",
      "description": "Theme switcher toggles between light and dark mode",
      "priority": "medium",
      "steps": [
        "Locate theme toggle button",
        "Click to switch theme",
        "Verify CSS variables change",
        "Verify state persists on reload"
      ],
      "passes": false,
      "last_tested": null,
      "notes": ""
    }
  ]
}
```

### 목표

- **Initializer Agent**: 프로젝트 요구사항을 파싱해 위 형태의 JSON 생성
- **Coding Agent**: 매 세션마다 파일을 읽어 `passes=false`인 기능 중 하나를 선택, 구현 후 상태 업데이트

## 학습 목표

1. 텍스트 기반 TODO와 구조화된 feature tracking의 차이를 이해한다.
2. JSON Schema를 사용해 일관성을 강제하는 방법을 익힌다.
3. "추가/삭제 금지, 상태만 업데이트" 원칙의 중요성을 체감한다.
4. 에이전트가 feature list를 "작업 선택 알고리즘"에 사용하는 패턴을 구현한다.

## 요구사항 (Student Task)

### Task 1: Initializer Agent - Feature List 생성

`create_feature_list(project_spec: str) -> dict`를 구현하라.

**입력**:

```
"Build a simple blog: users can create posts, view post list, and delete posts."
```

**출력** (예시):

```json
{
  "features": [
    {
      "id": "feature-001",
      "category": "functional",
      "description": "User can create a new blog post",
      "priority": "high",
      "steps": ["Navigate to create page", "Fill title and content", "Click submit", "Verify post appears in list"],
      "passes": false,
      "last_tested": null,
      "notes": ""
    },
    ...
  ]
}
```

**제약**:

- 모든 기능은 초기 `passes=false`
- `id`는 고유해야 함 (예: `feature-{counter}`)
- 각 기능은 최소 2개 이상의 검증 단계(`steps`)를 가져야 함

### Task 2: Coding Agent - Feature 선택 및 업데이트

`select_next_feature(feature_list: dict) -> dict`를 구현하라.

**선택 로직**:

1. `passes=false`인 기능들 중
2. `priority`가 가장 높은 것 (high > medium > low)
3. 동일 priority면 `id` 순서

**업데이트 함수**: `update_feature_status(feature_id: str, passes: bool, notes: str)`

- 기능을 완료하면 `passes=true`, `last_tested=현재시간`, `notes=구현 요약`
- **절대 금지**: 기능 삭제, description 변경, steps 변경

## 구현 가이드

### JSON Schema (검증용)

```python
FEATURE_SCHEMA = {
    "type": "object",
    "properties": {
        "id": {"type": "string", "pattern": "^feature-\\d+$"},
        "category": {"type": "string", "enum": ["functional", "ui", "performance", "security"]},
        "description": {"type": "string", "minLength": 10},
        "priority": {"type": "string", "enum": ["high", "medium", "low"]},
        "steps": {"type": "array", "minItems": 2},
        "passes": {"type": "boolean"},
        "last_tested": {"type": ["string", "null"]},
        "notes": {"type": "string"}
    },
    "required": ["id", "description", "passes"]
}
```

### 파일 저장 위치

```
project_root/
  feature_list.json         # 이 파일을 Git에 커밋
  .gitignore               # feature_list.json.bak 등은 무시
```

## 실패 모드 / 주의점

### 1. 에이전트가 기능을 제거/변경하려 시도

**문제**: "이 기능은 너무 어려워, 삭제하자"  
**해결**: System Prompt에 명시:

```
It is UNACCEPTABLE to remove or edit feature descriptions.
You may ONLY update the "passes", "last_tested", and "notes" fields.
```

### 2. 테스트 없이 `passes=true` 설정

**문제**: 코드만 작성하고 검증 없이 완료 표시  
**해결**: `update_feature_status` 호출 전 반드시 `steps`의 모든 항목 수행 강제

### 3. Feature list 파일 포맷 손상

**문제**: 수동 편집/병합 충돌로 JSON이 깨짐  
**해결**:

- 로딩 시 JSON validation
- 실패 시 `.backup` 파일에서 복구

### 4. 우선순위가 모호할 때

**문제**: 모든 기능이 `priority=high`  
**해결**: Initializer Agent에게 명확한 우선순위 기준 제공 (예: 핵심 기능 > UI > 최적화)

## 테스트 (제공/권장)

### 제공 테스트

```python
def test_create_feature_list():
    spec = "Build a todo app: add, list, delete todos"
    result = create_feature_list(spec)

    assert "features" in result
    assert len(result["features"]) >= 3  # 최소 3개 기능
    assert all(f["passes"] == False for f in result["features"])
    assert all("id" in f and "description" in f for f in result["features"])

def test_select_next_feature():
    feature_list = {
        "features": [
            {"id": "feature-001", "priority": "low", "passes": False},
            {"id": "feature-002", "priority": "high", "passes": False},
            {"id": "feature-003", "priority": "high", "passes": True},
        ]
    }
    next_feature = select_next_feature(feature_list)
    assert next_feature["id"] == "feature-002"  # high priority, not done

def test_update_feature_immutability():
    # 기능의 description을 변경하려는 시도 감지
    with pytest.raises(ValueError):
        update_feature_status("feature-001", description="Changed!")  # 금지됨
```

## 확장 과제 (선택)

### 1. 자동 우선순위 추론

Initializer Agent가 기능 간 의존성을 분석해 우선순위 자동 설정:

```json
{
  "id": "feature-001",
  "dependencies": [],  // 독립 기능
  "priority": "high"
}
{
  "id": "feature-002",
  "dependencies": ["feature-001"],  // 001이 완료되어야 함
  "priority": "medium"
}
```

### 2. 진행률 대시보드

```python
def get_progress_summary(feature_list: dict) -> dict:
    total = len(feature_list["features"])
    passed = sum(1 for f in feature_list["features"] if f["passes"])
    return {
        "total": total,
        "completed": passed,
        "percentage": round(passed / total * 100, 1),
        "by_category": {...}  # 카테고리별 진행률
    }
```

### 3. Feature Estimation

각 기능에 예상 소요 시간(토큰 수 또는 세션 수)을 추가하고, Coding Agent가 세션 시작 시 "이번 세션에 완료 가능한가?"를 판단.

## 실전 적용 (Main Scenario)

### Initializer Agent Workflow

```python
# 1. 사용자 요구사항 파싱
user_request = "Build a chat app like claude.ai"

# 2. LLM으로 세부 기능 생성
features = llm.invoke(f"Break down this into 50+ testable features: {user_request}")

# 3. 구조화 및 저장
feature_list = create_feature_list(features)
save_json("feature_list.json", feature_list)
git_commit("Initial feature list")
```

### Coding Agent Workflow

```python
# 매 세션 시작
feature_list = load_json("feature_list.json")
next_feature = select_next_feature(feature_list)

print(f"Working on: {next_feature['description']}")

# 구현 + 테스트
implement_feature(next_feature)
test_result = run_end_to_end_test(next_feature["steps"])

if test_result.passed:
    update_feature_status(next_feature["id"], passes=True, notes="All steps verified")
    save_json("feature_list.json", feature_list)
    git_commit(f"Implement {next_feature['id']}: {next_feature['description']}")
```
