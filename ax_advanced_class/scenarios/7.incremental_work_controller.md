# 7) Incremental Work Controller (점진적 작업 제어)

## 개발 Principle (Context Engineering 관점)

- **One Feature at a Time**: Long-running agent의 가장 큰 실패 모드는 "한 번에 모든 것을 구현하려는 시도"다. 이는 컨텍스트 윈도우 부족, 미완성 코드, 다음 세션의 혼란을 야기한다.
- **Scope Limiting as Context Control**: 에이전트에게 "이번 세션에는 이것만 해"라는 명확한 경계를 주면, **불필요한 컨텍스트 탐색을 방지**한다.
- **Complete Before Next**: 현재 기능을 완전히 끝내지 않고 다음으로 넘어가면, 다음 세션은 "미완성 작업을 이해하는 데" 컨텍스트를 낭비한다.
- **Natural Checkpoints**: 기능 단위는 자연스러운 체크포인트다. 각 기능 완료 시 clean state를 만들면, 세션 경계를 자유롭게 둘 수 있다.

## 시나리오 (Long-Running Agent 맥락)

### 배경
Anthropic 아티클의 핵심 문제:
> **초기 실패**: 에이전트가 claude.ai clone을 "one-shot"으로 구현하려 시도 → 컨텍스트 부족으로 중단 → 다음 세션이 미완성 코드를 발견하고 혼란

**해결책**: 에이전트에게 "한 번에 하나의 기능만 구현하라"고 명시적으로 지시.

### 예시: Before & After

#### ❌ Before (No Controller)
```
[Session 1]
Agent: I'll build the entire chat app!
- Created 50 files
- Half-implemented authentication
- Started message streaming but didn't finish
- Context window exhausted at 70% completion
→ Session ends with broken state

[Session 2]
Agent: What... happened here? Let me guess what was intended...
- Spends 30 minutes understanding incomplete code
- Tries to fix authentication but breaks it more
→ Productivity drops
```

#### ✅ After (With Controller)
```
[Session 1]
Controller: Next feature is feature-002 (New chat button)
Agent: Working on feature-002 only.
- Implemented NewChatButton component
- Added tests
- Verified end-to-end
- Marked feature-002 as complete
- Committed clean state
→ Session ends with working app + 1 new feature

[Session 2]
Controller: Next feature is feature-003 (Theme switcher)
Agent: Working on feature-003 only.
- Previous work is clean, I can start immediately
- Implemented ThemeSwitcher
- ...
```

### 목표
에이전트가:
1. 매 세션마다 **하나의 기능만** 선택
2. 그 기능을 **완전히** 구현 (코드 + 테스트 + 문서)
3. 완료 전에는 **다른 기능으로 전환하지 않음**

## 학습 목표

1. "Scope creep"를 막는 제어 메커니즘을 구현한다.
2. Feature selection 알고리즘을 설계한다 (priority, dependency 고려).
3. "완료"의 정의를 명확히 한다 (코드 + 테스트 + 문서 + 커밋).
4. System Prompt로 행동을 제약하는 방법을 익힌다.

## 요구사항 (Student Task)

### Task 1: Feature 선택 알고리즘
`select_next_feature(feature_list: dict) -> dict | None`을 구현하라.

**선택 규칙**:
1. `passes=false`인 기능만 후보
2. Priority 순서: `high` > `medium` > `low`
3. 같은 priority면 `id` 오름차순
4. (선택) Dependency 체크: `dependencies` 필드가 있으면 선행 기능이 완료되었는지 확인

**반환**:
- 선택된 feature 객체
- 모든 기능이 완료되었으면 `None`

**예시**:
```python
feature_list = {
    "features": [
        {"id": "feature-001", "priority": "high", "passes": True},
        {"id": "feature-002", "priority": "high", "passes": False},
        {"id": "feature-003", "priority": "medium", "passes": False},
    ]
}

result = select_next_feature(feature_list)
assert result["id"] == "feature-002"  # High priority, not done
```

### Task 2: Work Session Controller
`run_feature_session(feature: dict, agent: Agent) -> bool`를 구현하라.

**동작**:
1. 에이전트에게 feature 정보 전달 (description + steps)
2. System Prompt에 "이 기능만 구현하라" 명시
3. 에이전트 실행
4. 완료 조건 체크:
   - 모든 `steps`가 통과했는가?
   - 코드가 커밋되었는가?
   - Feature list에 `passes=true` 업데이트되었는가?
5. 완료 시 `True`, 미완료 시 `False` 반환

**제약**:
- 에이전트가 다른 기능을 건드리면 경고 + 롤백
- 완료 전에 세션 종료 시도하면 "완료하지 않았습니다" 메시지

### Task 3: Scope Enforcement
`check_scope_violation(feature_id: str, changed_files: List[str]) -> bool`를 구현하라.

**목적**: 에이전트가 현재 기능과 관련 없는 파일을 수정했는지 감지

**예시**:
```python
# feature-002는 "NewChatButton" 구현
feature_id = "feature-002"
changed_files = [
    "src/components/NewChatButton.tsx",
    "src/components/NewChatButton.test.tsx",
    "src/components/Sidebar.tsx",  # 이건 feature-005 범위
]

violated = check_scope_violation(feature_id, changed_files)
assert violated == True  # Sidebar는 현재 기능 범위 밖
```

**판단 로직** (간단 버전):
- Feature description에서 핵심 키워드 추출 (예: "NewChatButton")
- 변경된 파일 이름에 해당 키워드가 있는지 확인
- 없으면 scope violation

## 구현 가이드

### Priority 비교
```python
PRIORITY_ORDER = {"high": 3, "medium": 2, "low": 1}

def compare_features(f1: dict, f2: dict) -> int:
    """f1이 우선순위 높으면 -1, f2가 높으면 1, 같으면 0"""
    p1 = PRIORITY_ORDER.get(f1["priority"], 0)
    p2 = PRIORITY_ORDER.get(f2["priority"], 0)
    
    if p1 != p2:
        return -1 if p1 > p2 else 1
    
    # Priority 같으면 id 순서
    return -1 if f1["id"] < f2["id"] else 1
```

### Dependency 체크 (확장)
```python
def has_unmet_dependencies(feature: dict, feature_list: dict) -> bool:
    """선행 기능이 완료되지 않았으면 True"""
    if "dependencies" not in feature:
        return False
    
    for dep_id in feature["dependencies"]:
        dep_feature = next((f for f in feature_list["features"] if f["id"] == dep_id), None)
        if not dep_feature or not dep_feature["passes"]:
            return True  # 선행 기능이 미완료
    
    return False
```

### System Prompt 생성
```python
def create_focused_prompt(feature: dict) -> str:
    return f"""
You are working on a SINGLE feature in this session.

**CURRENT FEATURE**: {feature['id']}
**DESCRIPTION**: {feature['description']}

**REQUIREMENTS**:
{chr(10).join(f"- {step}" for step in feature['steps'])}

**RULES**:
1. Work ONLY on this feature. Do NOT touch unrelated files.
2. Complete ALL requirements before ending the session.
3. Write tests to verify each requirement.
4. Commit your work with message: "feat: {feature['description']}"
5. Update feature_list.json to mark this feature as passes=true

DO NOT work on any other feature, even if it seems related.
"""
```

### Git Diff로 변경 파일 추출
```python
def get_changed_files() -> List[str]:
    """마지막 커밋 이후 변경된 파일 목록"""
    result = subprocess.run(
        ["git", "diff", "--name-only", "HEAD"],
        capture_output=True,
        text=True
    )
    return result.stdout.strip().split("\n")
```

## 실패 모드 / 주의점

### 1. 에이전트가 "거의 완료"라고 주장하며 넘어가려 함
**문제**: "NewChatButton은 90% 완성, 다음 기능으로 가겠습니다"  
**해결**: 완료 조건을 **명확히** 정의하고 자동 검증
```python
def is_feature_complete(feature: dict) -> bool:
    # 1. 모든 steps가 테스트 통과
    # 2. Git에 커밋됨
    # 3. Feature list 업데이트됨
    return all_tests_pass and is_committed and feature["passes"]
```

### 2. 기능 간 의존성이 있을 때
**문제**: feature-005 (메시지 전송)는 feature-003 (채팅방 생성)이 선행되어야 함  
**해결**: `dependencies` 필드 + selection algorithm에서 체크

### 3. "이 버그도 같이 고치자"는 유혹
**문제**: 현재 기능 작업 중 다른 기능의 버그 발견 → 같이 고치려 함  
**해결**: System Prompt에 명시:
```
If you discover bugs in OTHER features, note them in claude-progress.txt 
but DO NOT fix them now. Stay focused on your assigned feature.
```

### 4. 기능이 너무 크게 정의됨
**문제**: "feature-001: Implement entire authentication system" (20시간 작업)  
**해결**: Initializer Agent에게 "각 기능은 1-3시간 내 완료 가능하게 쪼개라" 지시

### 5. 테스트 실패해도 다음으로 진행
**문제**: 에이전트가 테스트 실패를 무시하고 `passes=true` 설정  
**해결**: `run_feature_session`에서 자동 검증
```python
test_result = run_all_tests()
if not test_result.success:
    return False  # 세션 실패로 처리
```

```python
def test_select_next_feature_priority():
    """Priority 순서대로 선택"""
    features = {
        "features": [
            {"id": "feature-001", "priority": "low", "passes": False},
            {"id": "feature-002", "priority": "high", "passes": False},
            {"id": "feature-003", "priority": "medium", "passes": False},
        ]
    }
    
    next_f = select_next_feature(features)
    assert next_f["id"] == "feature-002"

def test_select_next_feature_all_complete():
    """모든 기능 완료 시 None"""
    features = {
        "features": [
            {"id": "feature-001", "priority": "high", "passes": True},
        ]
    }
    
    next_f = select_next_feature(features)
    assert next_f is None

def test_scope_violation_detection():
    """범위 벗어난 파일 수정 감지"""
    feature = {"id": "feature-002", "description": "Implement NewChatButton component"}
    changed_files = [
        "src/components/NewChatButton.tsx",
        "src/components/ThemeSwitcher.tsx",  # 다른 기능
    ]
    
    violated = check_scope_violation(feature["id"], changed_files)
    assert violated == True

def test_dependency_check():
    """선행 기능 미완료 시 선택 불가"""
    features = {
        "features": [
            {"id": "feature-001", "priority": "high", "passes": False, "dependencies": []},
            {"id": "feature-002", "priority": "high", "passes": False, "dependencies": ["feature-001"]},
        ]
    }
    
    next_f = select_next_feature(features)
    assert next_f["id"] == "feature-001"  # 002는 001에 의존하므로 스킵
```

## 확장 과제 (선택)

### 1. Time-boxed Sessions
각 feature에 예상 시간을 부여하고, 시간 초과 시 경고:
```python
feature["estimated_time"] = "2 hours"

def run_feature_session(feature, agent):
    start_time = time.time()
    # ... agent work ...
    elapsed = time.time() - start_time
    
    if elapsed > feature["estimated_time"] * 1.5:
        print("⚠️  Feature taking longer than expected. Consider splitting.")
```

### 2. Multi-Agent Parallelization
서로 독립적인 기능들은 별도 에이전트가 병렬로 작업:
```python
# feature-002와 feature-005가 독립적
agent1.work_on("feature-002")  # 병렬
agent2.work_on("feature-005")  # 병렬

# 나중에 merge
```

### 3. Adaptive Priority
에이전트가 작업하며 priority를 동적으로 조정:
```python
# feature-003을 시도했지만 기술적으로 너무 어려움
# → priority를 낮추고 나중에 재시도
adjust_priority("feature-003", "low", reason="Requires more research")
```

## 실전 적용 (Main Scenario)

### Coding Agent Main Loop
```python
def coding_agent_main():
    while True:
        # 1. 상태 복원
        state = recover_session_state()
        feature_list = load_json("feature_list.json")
        
        # 2. 다음 기능 선택
        next_feature = select_next_feature(feature_list)
        
        if next_feature is None:
            print("🎉 All features complete!")
            break
        
        print(f"📝 Working on: {next_feature['id']} - {next_feature['description']}")
        
        # 3. Focused prompt 생성
        prompt = create_focused_prompt(next_feature)
        
        # 4. 에이전트 실행
        success = run_feature_session(next_feature, agent)
        
        if not success:
            print(f"❌ Failed to complete {next_feature['id']}")
            # 실패 원인 분석 후 재시도 또는 스킵
        
        # 5. Scope violation 체크
        changed_files = get_changed_files()
        if check_scope_violation(next_feature["id"], changed_files):
            print("⚠️  Scope violation detected! Rolling back...")
            subprocess.run(["git", "reset", "--hard", "HEAD"])
```
