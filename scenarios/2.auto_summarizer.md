## 2) Auto Summarizer (자동 요약 기반 컨텍스트 압축)

### 개발 Principle (Context Engineering 관점)
- **손실 압축(Lossy Compression)**: 대화 전체를 원문 그대로 유지하는 대신, 중요한 의미만 남긴 “요약”으로 과거 컨텍스트를 압축한다.
- **계층형 메모리(Hierarchical Memory)**:  
  - **최근 메시지**: 원문을 유지(정확도/상세)  
  - **과거 메시지**: 요약으로 유지(압축/안정)  
  - **불변 정책**: System Prompt는 최상위 계층으로 고정
- **요약은 제품 기능**: 요약 품질이 에이전트 품질에 직결된다. 따라서 **요약 형식(스키마)와 검증**이 필요하다.

### 시나리오 (실습 맥락)
- **상황**: 채팅 루프에서 매 5번째 메시지마다 정리 작업을 수행한다.
- **도구/가정**: `llm_summarize(text)` 모의 함수가 제공되며 `"Summary of [text]"`를 반환한다.
- **문제**: 마지막 5개 메시지는 원문으로 남기고, 그 이전 메시지는 요약 1개로 압축한다.

### 학습 목표
- “Rolling Window”와 달리, **삭제 대신 요약으로 기억을 보존**하는 패턴을 익힌다.
- 요약을 **SystemMessage 형태로 주입**하는 이유(정책 우선/컨텍스트 상단 배치)를 이해한다.

### 요구사항 (Student Task)
`compress_context(history)`를 구현하라.
- **대상**: `messages` 중 **마지막 5개를 제외한 과거 메시지**
- **동작**:
  - 과거 메시지 텍스트를 하나로 합쳐 `llm_summarize` 호출
  - 과거 메시지를 제거하고, 대신 아래 형태의 SystemMessage 1개로 대체
    - `SystemMessage(content="Previous summary: ...")`
- **반드시 만족**:
  - System Prompt(인덱스 0)는 유지
  - 결과적으로 메시지 수가 감소(또는 과거 메시지가 0개면 변화 없음)

### 입력/출력 스키마(권장)
- **입력**
  - `history.messages: List[Message]`
  - `llm_summarize(text: str) -> str`
- **출력**
  - 압축된 `history.messages`

### 요약 프롬프트 설계(실무 팁)
실무에서는 요약을 자유 텍스트로 두기보다 “구조화”하면 후속 추론이 안정적이다.
- **권장 요약 구조(예시)**
  - 주요 목표 / 결정사항 / 미해결 이슈 / 제약 / 용어 정의
- **금지 규칙(예시)**
  - PII 포함 금지(시나리오 5 연계)
  - 불확실한 사실은 “추정/미확인” 표기

### 실패 모드 / 주의점
- **요약이 정책을 덮어씀**: 요약을 SystemMessage로 넣을 때, 위치/우선순위를 잘못 설계하면 모델이 요약을 “정책”으로 오해할 수 있다.  
  - 권장: “Previous summary”처럼 **요약임을 명시**
- **요약 드리프트(요약의 요약 반복)**: 여러 번 요약하면 사실이 변형될 수 있다.  
  - 권장: 원문 일부(결정사항 등)만 보존하거나, 요약을 누적하지 말고 “정본(ground truth)”를 별도 상태로 유지(시나리오 6)

### 테스트(제공/권장)
- **제공 테스트 아이디어**
  - 15개 메시지 → 압축 후 리스트 크기 감소
  - `"Previous summary:"` 문자열 포함 확인
- **추가 테스트(권장)**
  - 메시지가 5개 이하인 경우: 변화 없음
  - 과거 메시지에 System/Tool 메시지가 섞인 경우: 어떤 역할을 요약 대상에 포함할지 정책 결정

### 확장 과제(선택)
- **요약 스키마 JSON 출력**: `{"decisions":[...],"todos":[...],"constraints":[...]}` 형태로 만들고 파싱/검증
- **요약 품질 평가**: 원문 대비 핵심 정보 보존율(정답키 기반), 환각 여부 체크리스트 설계
