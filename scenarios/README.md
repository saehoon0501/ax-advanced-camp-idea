## Context Engineering 실습 시나리오 모음 (1~9)

### 이 폴더의 목적
이 폴더는 “AI Agent 개발 방법론 심화” 실습에서 **Context Engineering(컨텍스트 엔지니어링)** 핵심 패턴을 작은 과제로 쪼개 연습하도록 구성한 문서 모음이다.  
각 문서는 “원칙(Principle) → 시나리오 → 요구사항 → 실패 모드 → 테스트/평가 → 확장 과제” 순서로 작성되어 있어, 그대로 과제 핸드아웃으로 배포할 수 있다.

### Context Engineering 핵심 프레임(요약)
- **컨텍스트 예산 관리**: 모델 입력 토큰은 제한되어 있으며, 한도 이전부터 품질 저하(Pre-rot)가 생긴다.
- **컨텍스트 계층화**: 고정 정책(System) / 동적 근거(RAG) / 최근 대화 / 요약 / 구조화 상태(State)를 분리해 관리한다.
- **노이즈 제거**: 툴 출력/로그/장황한 설명은 관측값 컴팩션과 스크래치패드로 줄인다.
- **안전 컨텍스트**: PII/민감정보는 모델 입력 전에 비식별화(Policy-as-Code)한다.
- **라우팅**: 의도에 따라 툴/페르소나를 동적으로 선택해 “보이는 컨텍스트”를 최소화한다.

### 시나리오별 한 줄 요약
- **1. Rolling Window**: 토큰 한도를 지키되 System Prompt는 고정 보존하고 오래된 메시지를 제거한다.
- **2. Auto Summarizer**: 오래된 히스토리를 요약 1개로 압축해 의미를 보존한다.
- **3. Tool Output Trimmer**: 장황한 툴 JSON을 스키마 기반으로 핵심만 남겨 컨텍스트를 절약한다.
- **4. RAG Injector**: 질문에 필요한 문서만 선별해 근거 컨텍스트로 주입한다.
- **5. PII Sanitizer**: 개인정보가 모델 컨텍스트로 들어가기 전에 마스킹/토큰화한다.
- **6. State Extractor**: 장기 정보는 대화 대신 구조화 상태(UserProfile 등)로 오프로딩한다.
- **7. Tool Selector**: 과업에 필요한 도구만 노출해 혼란/비용/리스크를 줄인다.
- **8. Thought Scratcher**: THOUGHT(추론)는 저장 최소화, ANSWER만 히스토리에 남긴다.
- **9. Dynamic Persona**: 의도에 따라 페르소나(모드)를 바꿔 출력 규칙/스타일을 최적화한다.

### 권장 진행 순서(수업용)
1 → 2 → 6 → 5 → 3 → 4 → 7 → 8 → 9  
(예산/압축/상태/안전 → 툴/검색/라우팅 → 로그 분리/모드 전환)

### 평가 체크리스트(공통)
- **정확성**: 요구사항(보존/제한/치환/선별)이 테스트로 검증되는가?
- **예산 친화성**: 불필요한 텍스트를 컨텍스트에 넣지 않는가?
- **안전성**: PII/고위험 도구 노출이 최소화되는가?
- **회복 탄력성**: 포맷 불일치/키 누락/모호한 질의 같은 실패 모드에 폴백이 있는가?
